# 跨项目对比与压力问题

> 两个项目都用了 MCP、SSE 和评测，但解决的问题不同。对比时先说「各自解决什么」，再说「为什么这样取舍」。

## 一张表看差异

| 维度 | THINGJS 文档 RAG | 江中智能助手 |
| --- | --- | --- |
| 业务问题 | 官方文档太多，查不到、答不准 | 车间里查制度、查设备、办业务流程 |
| 知识形态 | 260 篇 Markdown + 117 个示例代码文件 | 制度 / 规程知识库 + 中台业务数据 + 三维场景 |
| 核心链路 | 索引 → 混合检索 → 精排 → 证据守卫 → 生成 | classify → route → act / 计划 / 固定子图 |
| MCP 角色 | 知识工具的提供方，向编辑器开放检索与问答 | MCP 工具的调用方，接中台查设备、工单、库存 |
| 前端形态 | Vue 3 问答页、检索页、引用 / 耗时 / 提示词检查器 | 浏览器宿主内的可移植对话模块、审批卡、场景回执 |
| 流式交互 | SSE 增量预览，`done` 才是权威结果 | SSE + 场景动作 + 人工确认 + 后台运行 |
| 质量证据 | 黄金集、逐题证据、三套门禁、配置版本 | 执行断言、逐题交付判定、裁判、人工标注、归因校准 |
| 失败边界 | 检索不到、引用不匹配、索引发布失败 | 工具失败、缺参、越权、写操作状态不明 |
| 最适合讲 | RAG 全链路与检索评估 | Agent 编排、工具边界与恢复 |

## 共同点

- **模型负责理解与提议，程序负责边界与结算**：两个项目都没有把权限、参数校验、写操作交给模型自由发挥。
- **证据优先**：RAG 用引用和检索证据；江中用执行回执、交付判定和人工标注。
- **可回归**：都维护题集、指标和发布门禁，修改后能判断有没有退化。
- **前端不是「最后套一层」**：SSE 解析、取消、重试、审批、场景回执都在前端有明确状态机。

## 面试问题

### Q01 两个项目都用了 MCP，有什么不同？ {#q01}

**参考回答**

江中把助手接到中台，助手服务端是 MCP 工具的**调用方**，工具返回设备、工单等只读业务数据；重点在参数、权限和多步编排。

THINGJS RAG 通过 MCP 向编辑器开放检索和问答，项目是知识工具的**提供方**；重点在证据质量、索引版本和检索服务的稳定性。

一句话：一个要保证「查得对、做得稳」，一个要保证「答得有据、发得安全」。

**可能追问**

MCP 工具谁注册、谁执行、失败怎么回传？江中由宿主或中台上报目录，服务端只看到本次目录；RAG 由服务端暴露检索 / 问答工具，编辑器调用后拿结构化结果。

### Q02 两个项目怎么判断「做得好」？给什么证据？ {#q02}

**参考回答**

江中：用一条真实线上请求说明是否选对工具、参数是否正确、后续动作是否合理、异常时怎么结束。

THINGJS RAG：展示检索与回答评测的逐题记录、证据是否被采用、答案和引用是否匹配，以及新索引是否通过发布检查。

报数字前先说清测试条件、题集分母和统计对象。比如「24 题可回答生成集上裁判幻觉 0」，不要说成「幻觉 0」。

### Q03 只允许讲一次失败复盘，你选什么？ {#q03}

**参考回答**

选一条自己能核对的记录。可以用江中的「设备存在但无告警，仍需定位」，也可以用 RAG 的「目标类召回了却没有进入上下文」。

按「现象 → 看到的证据 → 问题在哪一层 → 修改了什么 → 如何复验」来讲。把示例问法替换成自己实际核对过的脱敏材料。

### Q04 中国移动网络拓扑 vs 江中场景定位 {#q04}

**参考回答**

中国移动：网络资源拓扑，重点是 3D / 2D 布局、线路关系和聚合下钻。

江中：对话式业务助手，场景定位只是其中一环，重点是**分类 → 规划 → 执行**、工具、审批和回执。

两者都用 ThingJS，但一个以拓扑浏览为主体，一个以对话和业务办理为主体。

| 维度 | 中国移动网络拓扑 | 江中助手场景 |
| --- | --- | --- |
| 目标 | 网络资源的三维可视化与多层级浏览 | 对话之后的设备定位与场景动作 |
| 数据 | 集团 / 省 / 区域、设备、线路、业务类型 | 设备、告警、工单、场景方法目录 |
| 交互 | 3D / 2D 切换、线路高亮、双击下钻、筛线、相机飞行 | 聚焦、飞行、告警高亮、场景回执 |
| 难点 | 复杂拓扑自动布局、平行线路、聚合下钻 | 意图到动作、权限、人工确认、回执 |
| 前端重点 | 图布局、相机、标签、聚合 | 流式对话、审批卡、状态机、宿主模块 |

面试时不要把这两个三维场景混着讲。

### Q05 你更像前端还是 AI 应用工程师？ {#q05}

**参考回答**

我的底子是前端，但最近两个项目是端到端交付：Vue 3 对话前端、Express 服务端、智能体编排、检索与评测。

所以更像**偏前端的 AI 应用工程师**：能把模型能力接进业务，也能把交互、流式、审批和恢复做完整。

### Q06 面试官偏 RAG、Agent 或前端时，怎么选讲法？ {#q06}

**参考回答**

- 偏 RAG / 搜索 / 知识工程：先讲 THINGJS，再补江中的 Agent 编排。
- 偏 Agent / 工作流 / 业务落地：先讲江中，再补 THINGJS 的检索评估。
- 偏前端：先讲两个项目的前端状态机，再讲后端链路。重点说 SSE、取消、重试、审批和场景回执。
