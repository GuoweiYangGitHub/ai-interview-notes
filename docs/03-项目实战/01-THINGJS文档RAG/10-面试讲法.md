# THINGJS 文档 RAG · 面试讲法
> 一句话定位：按时间盒讲清「文档问答 + 引用 + 评测门禁 + 可运维」的工程系统，数字只带一份口径。

## 30 秒总览

> 面向 ThingJS 官方文档的 RAG 问答系统：260 篇 Markdown + 117 个示例代码文件 → 9,366 个语义块；Qwen3-Embedding-4B（2,560 维）向量 + MiniSearch/jieba BM25；检索侧「意图识别 → 查询计划 → 双路召回 → RRF → 精确符号置顶 → 父块补全」，生成侧 LangChain 0.3 LCEL + JSON + 回答形态分类 + 证据守卫 + 会话记忆；Web、MCP、评测平台三个入口。

**一句话定位**：不是通用聊天，是「文档问答 + 引用 + 评测门禁 + 可运维」的工程系统。

## 60 秒讲法

> 「我最近做的是一个 ThingJS 文档 RAG 系统，用 LangChain JS 0.3 重建。它把 260 篇官方文档和 117 个示例代码文件切成 9,366 个语义块，用 Qwen3-Embedding-4B 做 2560 维向量索引，同时用 MiniSearch + jieba 做中文 BM25。检索不是简单 topK，而是先做意图识别和查询计划，处理别名、错拼、否定和多类问题，再向量 + BM25 双路召回、RRF 融合、精确符号置顶、父块补全；显式类名和代码题会扩大候选池，并用 SQLite 符号证据补强。
>
> 生成侧用结构化 JSON、回答形态分类、证据筛选、领域守卫和确定性清洗控制幻觉，回答带引用和置信度；代码/报错题走独立链路。多轮场景不是把历史全塞进去，而是按会话要求、摘要、最近问答组和相关历史组装，用五阶段 token 预算和 trace 控制；20 轮实测输入 token 降了 29.6%，当前问题重复从 20 次降到 0。
>
> 质量上有一套独立的评测平台：core 100 题检索 + 30 题生成 + 12 题裁判校准，另加 161 题覆盖集、30 题真实问法、20 题代码/报错题；三套门禁加基线对比和配置版本。最近一次检索 94/94；生成门禁最近一次 23/24 被拦截（幻觉 0），问题进入回归验证闭环，历史通过版本是 24/24、裁判 95.8%。工程上还有索引热更新与失败回滚、点踩到问题到人工确认的闭环、Prometheus 指标和调用链观测。」

## 3 分钟讲法

1. **问题**（20s）：ThingJS 文档多、术语密、口语化/错拼多、多来源冲突、模型容易编 API。
2. **整体架构**（30s）：三进程——前端 9966、服务端 9967、评测平台 9968；服务端分文档/索引/检索/生成/应用/运维六层。
3. **索引**（30s）：Markdown 结构解析 → 类/章节/成员切块 → 向量 + BM25 + 父块 → 版本目录 + manifest + BUILD_OK；文档变更走指纹 + 子进程 + active.json 热切换 + 门禁回滚。
4. **检索**（40s）：意图 → 查询计划（别名、错拼、实体、否定、视点）→ 向量/BM25 并行 → RRF → 每类公平/文件内优先/精确置顶 → 有界父块 → context。
5. **生成**（30s）：独立切题/追问判断 → 会话记忆组装（五阶段预算）→ Prompt（YAML 版本化；温度按声明绑定：回答 0、改写 0.2）→ LCEL + JSON 解析 → 形态分类 → 证据筛选 → 规则守卫（一次纠错）→ 确定性清洗 → 引用按正文重排 → 输出后置校验 → SSE；代码/报错走 `code-debug`。
6. **质量**（30s）：100/30/12 黄金集；检索 Hit@K/MRR/false-empty/禁止类；生成 schema/引用/路径/负例/裁判；绝对阈值 + 基线 + 配置版本 + 人工确认；发布检查聚合门禁、P0/P1、点踩率、空结果率、P95。
7. **结果**（20s）：检索 94/94、Member 26/26、false-empty 0；生成最近一次 23/24 被门禁拦截（幻觉 0），历史通过 24/24、裁判 95.8%；20 轮输入 -29.6%；服务端 392 个测试、评测 142 个、E2E 4 个。

## 口径提醒

同一件事在不同阶段的文档里可能有两种写法，面试时要按“当前口径”说：

1. **切块**：`800/200` 是旧 H3 基线；当前活动索引的切块指纹是 `md-h2-merge-h3-900-1200-v4-symbol-spans`，即 target 900 / max 1200 / overlap 150。
2. **采纳窗口**：检索页早期写法是「每类 5 条」；评测平台和当前实现按「普通题 5 条、多类/多成员 `n×3`」计分，以响应 `effectiveTopK` 为准。
3. **生成门禁**：`24/24、95.8%` 是 2026-11-18 02:58 的历史通过版本；最新一次是 `23/24、91.3%、confidence 96.7%`，被门禁拦截并进入回归闭环。不要把 24/24 说成“最近一次”。
4. **合成向量**：活动索引 `20261118.16.00.00` 用 `--synthesize-from` 复用旧成员向量（9,290 合成 + 76 实际 embedding，构建 4.4 分钟）。生成门禁曾因此未通过，当前该版本仅供手动测试；正式发布应改用真实合并块 embedding。
5. **幻觉 0**：指 30 题生成集里 24 题可回答的裁判口径，不是线上全量。
6. **限流**：进程内单机限流，不是全局限流。

## 面试官可能追问的短答

- **「为什么不用现成的 RAG 平台？」**：需求是内网、网关鉴权、ThingJS 领域规则、逐题基线、MCP、问题闭环；平台能跑通 demo，但改不动这些契约。
- **「为什么不微调模型？」**：文档更新频繁、需要引用和可解释、幻觉要可控；RAG + 规则 + 评测更合适，微调作为后续补充。
- **「为什么不用 GraphRAG？」**：当前问题以类/成员/示例为主，结构切块 + 精确召回已覆盖；GraphRAG 成本和复杂度更高，先用评测证明需要。
- **「怎么处理文档冲突？」**：契约和提示词有 api/editor/example/project 优先级与并列策略；当前检索链还没生成 `conflicts`，是下一步。
- **「怎么处理权限？」**：网页走网关会话，机器走 Bearer；管理入口按 `WEB_ADMIN_USERS`；运维接口默认本机。
- **「怎么保证不泄密？」**：`.env` 不提交/不打印；日志脱敏；prompt 正文不进日志；门禁输出只留退出码；备份不含 `.env`。
- **「多轮记忆怎么控制 token？」**：先判断独立切题还是追问；独立切题跳过改写和摘要，追问只带相关片段 + 最后一组问答。回答总记忆上限 2,300 估算 token，改写/摘要/形态/回答/代码分阶段预算，最终请求用同一计数器复核；输出超限用 `finish_reason=length` 和实际 `completionTokens` 后置校验。
- **「重试会不会把旧回答又带回来？」**：请求带原用户/旧助手的 `clientId`，服务端按会话归属、角色和配对校验，排除原用户、指定旧助手和同一原问题下的其他旧尝试；本轮跳过摘要更新，失败/取消回答不进记忆。
- **「用户贴代码怎么处理？」**：单框里出现代码围栏、`new THING.`、`const/let/var`、报错/堆栈等特征就识别为 `code_debug`；检索查询截断到 2,000 字符，生成保留完整代码，走 `code-debug` 提示词，不执行代码，也不声称验证过修复。
- **「为什么先做回答形态分类？」**：不同问题要不同结构：创建、操作、对比、排错、简单事实。分类只决定格式段和领域规则，失败/低置信度回退 `simple`，不影响检索证据。
- **「门禁怎么防止拿旧结果放行？」**：配置版本由提示词、索引、回答模型、裁判模型、检索配置哈希生成；回归确认绑定版本，版本变化后旧确认 stale；发布检查只认当前版本下人工确认过的用例。
- **「最大的技术债？」**：单机限流/会话/索引、提示词不热更新、网关不执行输出上限只能后置校验、固定证据仍用字符估算、冲突检测未上线、融合分不可得。

## 收尾句

> 「这个项目对我来说最大的价值，不是把 RAG 跑通，而是把它做成了一个**可回归的工程系统**：每次改检索、改提示词、改文档，都有黄金集、门禁和发布检查告诉我有没有退化；线上每次回答都有 trace、证据和问题闭环可以追。这比单次 demo 更接近真实生产。」
