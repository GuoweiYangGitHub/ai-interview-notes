# THINGJS 文档 RAG · 3 分钟演讲稿

ThingJS 文档问答系统是面向 ThingJS 官方文档和示例代码的问答助手。用户可以用自然语言问类和成员怎么用，系统给出用法、示例和引用；有网页助手和 MCP 服务，共用一套检索和生成链路。

我负责的是前端展示页、助手服务端、MCP 服务和评测系统。

因为我们的知识库大部分都是 Markdown 文档、一部分代码示例和片段，所以切片不能按固定长度切。我们按 Markdown 的标题、段落和代码块结构来切，代码再按语法树拆到类和方法，尽量让一个成员的说明、签名和示例留在同一个片段里；同时保留父块，命中短片段后能把上下文补回来。

检索是混合检索，同时跑向量和 BM25 召回。向量负责中文口语和语义相近的表达，BM25 负责类名、方法名这种精确符号；两路结果用 RRF 按排名融合，再做精确符号置顶、类 / 成员配额和父块回填，最后交给模型生成。

索引按照文件指纹增量构建，校验清单后切激活指针，文档改动可以热更新，也可以设置发布门禁，发布门禁失败就回滚。

评测分检索和生成两层。检索层用 100 题，看预期类 / 成员有没有进候选，误空和分层指标也会一起看；生成层用 30 题，看引用、必提内容和空结果，再用 12 条样本校准裁判。用例还覆盖真实问法和代码题，门禁和配置版本绑定，不达线就阻断发布。

切片的大小跟着文档结构走，不是固定长度；混合检索同时解决语义和精确符号；引用只能保证出处是真的，不能保证结论站得住。
