## AI 质检（钢铁检测）

口述：钢铁表面缺陷质检 = **YOLO 定位分类已知缺陷** + **Qwen-VL 零样本看图分析**；Gradio 做人机审核台，SQLite 落记录。前面 VL 微调章节，这里是落地场景。

### 技术栈

| 模块       | 选型                           | 用途                 |
| ---------- | ------------------------------ | -------------------- |
| 目标检测   | **YOLOv12（Ultralytics）**     | 精确缺陷定位与分类   |
| 多模态分析 | **Qwen-VL**（OpenAI 兼容 API） | 零样本缺陷识别与分析 |
| Web 界面   | **Gradio**                     | 交互式质检工作台     |
| 数据库     | **SQLite**                     | 检测记录、审核状态   |
| 数据分析   | **matplotlib + numpy**         | EDA 可视化           |

```bash
pip install ultralytics gradio openai pillow numpy matplotlib
```

流水线直觉：YOLO 先框已知类缺陷 → VL 补「没见过的 / 要解释的」→ 人工在 Gradio 审核 → 结果进 SQLite。

### labelImg 标注工具

- 仓库：https://github.com/HumanSignal/labelImg
- 安装与运行：

```bash
pip install pyqt5
pip3 install labelImg
labelImg   # 运行
```

用于给缺陷画框，产出 YOLO 训练用标注（检测数据准备阶段）。

### 标注原则

每条框需带：**left / top / width / height / class**。

1. **框大小合适** — 矩形紧裹目标，别过大过小。
2. **多角度素材** — 正反、左前右前、左后右后、俯视等，保证泛化。
3. **遮挡也要标** — 目标被挡仍标注。
4. **小目标也要标** — 画面里的小缺陷不能漏。
5. **别标看不清的** — 人眼都分不清就不要标，避免误导模型。

口条：**钢铁质检 = YOLO 定位 + Qwen-VL 零样本分析 + Gradio 审核；标注紧框、多角度、遮挡/小目标要标，看不清不标。**

## 为什么数据增强对缺陷检测特别重要？

口述：缺陷数据天生「难」——**同类长得不像、异类长得像、每类就两百张**。增强不是锦上添花，是补这三短的刚需。

| 难点           | 表现                              | 增强对策                             |
| -------------- | --------------------------------- | ------------------------------------ |
| **类内差异大** | 同是划痕，可横可竖可斜            | **旋转、翻转**                       |
| **类间相似**   | 龟裂 vs 点蚀 易混                 | **对比度增强、锐化**（拉开纹理差异） |
| **数据量少**   | 每类约 **200 张**，远不够深度学习 | **Mosaic、MixUp、离线扩充**          |

口条：**缺陷检测：转翻打类内、对比锐化分易混、Mosaic/MixUp 补量。**

## 都有哪些常用的增强技术？

口述：缺陷检测增强分三层——**几何（位置朝向）**、**颜色/噪声（光照传感器）**、**YOLO 高级（Mosaic 等）**；落地再分 **训练时内置** vs **离线 Albumentations 扩盘**。

### 1. 几何变换：改缺陷位置与朝向

| 操作         | 工业动机         | 代码要点（PIL）                                   |
| ------------ | ---------------- | ------------------------------------------------- |
| 水平翻转     | 缺陷可左可右     | `img.transpose(Image.FLIP_LEFT_RIGHT)`            |
| 垂直翻转     | 朝向不固定       | `img.transpose(Image.FLIP_TOP_BOTTOM)`            |
| 旋转 90°     | 划痕横/竖/斜都有 | `img.rotate(90, expand=False)`                    |
| 小角度随机转 | 相机轻微偏斜     | `angle ~ U(-20,20)`；`rotate(..., fillcolor=128)` |

PIL 要点：`Image.open` 读图；`transpose` 翻；`rotate` 转（`expand=True` 防裁角，`fillcolor` 填空白）。

蓝条：钢铁划痕/裂纹方向位置随机 → 变换模拟工况，提泛化。

### 2. 颜色变换：模拟光照与材质

| 操作     | 工业动机               | 要点                                                        |
| -------- | ---------------------- | ----------------------------------------------------------- |
| 亮度     | 工业相机光源不稳       | `ImageEnhance.Brightness(img).enhance(1.3)`（>1 亮，<1 暗） |
| 对比度   | 拉清缺陷边缘           | `Contrast(...).enhance(1.4)`                                |
| 高斯噪声 | 传感器热噪声、电磁干扰 | `N(0,15)` 加到像素，`clip` 到 0～255                        |

蓝条：产线常见光照不稳 + 传感器噪声 → 让模型在差成像下仍认得出缺陷。

### 3. YOLO 高级增强（检测核心）

| 技术               | 做法               | 好处 / 参数                                                    |
| ------------------ | ------------------ | -------------------------------------------------------------- |
| **Mosaic**         | 4 张图拼成 1 张训  | 多样性↑、变相加大 BN batch、小目标更多；`mosaic=1.0`（默认开） |
| **MixUp**          | 半透明叠两图       | `α·img1+(1-α)·img2`，α 常 0.1～0.3；`mixup=0.15`               |
| **Copy-Paste**     | 把缺陷拷到另一张图 | 适合每图只有 1～2 个目标；`copy_paste=0.15`                    |
| **Random Erasing** | 随机遮一块         | 防过拟合（小数据尤甚）；`erasing=0.3`                          |

### 4. YOLO 内置 vs 离线增强

|            | YOLO 内置增强           | 离线增强                   |
| ---------- | ----------------------- | -------------------------- |
| 原理       | 每个 epoch 训练时随机变 | 训前先生成新图落盘         |
| 数据集大小 | **不变**                | **×N**                     |
| 适用       | 通用，训练自动开        | 总量极少、或稀有类要过采样 |

可**同时用**：内置靠 `model.train(...)` 参数；离线可用 `train_yolo_enhanced.py` 策略 4 + **Albumentations**。

**Albumentations（工业检测离线首选）**

- 专为 CV 的高性能增强库；**图 + 框 + mask 同步变换**。
- 比 PIL 快约 **10～100 倍**；变换种类 **300+**（模糊、畸变、天气等）。

口条：**几何打朝向，颜色噪声打工况，YOLO 靠 Mosaic/MixUp/Copy-Paste/擦除；内置随时变，离线用 Albumentations 扩盘。**

## 训练调优策略

口述：钢铁缺陷 YOLO 调优六板斧——先基线，再增强，再加大模型/输入，再离线扩数据，推理解锁 TTA，最后扫 **conf**。脚本入口常是 `train_yolo_enhanced.py`。

### 策略1：基线训练

```python
model = YOLO("yolo12n.pt")  # 预训练 nano
model.train(data=DATASET_YAML, epochs=100, batch=16, imgsz=640)
```

先立对照组，后面所有改动都跟它比。

### 策略2：数据增强调优

`epochs=150`，按缺陷特点拧增强：

| 参数                | 例值             | 动机         |
| ------------------- | ---------------- | ------------ |
| `fliplr` / `flipud` | 0.5              | 缺陷朝向任意 |
| `degrees`           | 15.0             | 小角度旋转   |
| `mosaic`            | 1.0              | 加强小目标   |
| `mixup`             | 0.15             | 提泛化       |
| `copy_paste`        | 0.15             | 每图目标少   |
| `hsv_h/s/v`         | 0.02 / 0.7 / 0.5 | 光照不均     |
| `erasing`           | 0.3              | 提鲁棒       |

### 策略3：更大模型 + 更大输入

```python
model = YOLO("yolo12s.pt")  # s 比 n 强
model.train(..., epochs=150, batch=8, imgsz=1280, cos_lr=True)
```

- `imgsz=1280`：细小缺陷细节保留更好。
- `cos_lr=True`：余弦退火，训练更稳。
- 代价：训/推更慢、显存暴涨 → 建议 **≥12GB** 显存。

### 策略4：离线数据增强

训前物理扩盘，尤其适合**少样本类**。Albumentations 例：

```python
# HorizontalFlip / VerticalFlip / RandomRotate90
# CLAHE：对比度受限自适应直方图均衡，增强缺陷可见性
# RandomBrightnessContrast / GaussNoise / ShiftScaleRotate
# bbox_params: format='yolo', min_visibility=0.3
```

和 YOLO 内置增强的区别：内置每 epoch 随机、盘上文件数不变；离线真正 ×N 张图 → **两者可结合**。

### 策略5：测试时增强（TTA）

```python
results = model.predict(source=test_dir, conf=0.25, augment=True)
# augment=True：同一张图多次变换，预测取并集
```

- 优点：无需重训即可抬精度。
- 缺点：推理大约慢 **2～3 倍**。

### 策略6：置信度阈值调优

默认 `conf=0.25`，最优随数据和业务变。扫一遍：

```python
thresholds = [0.1, 0.15, 0.2, 0.25, 0.3, 0.35, 0.4, 0.5]
for conf in thresholds:
    results = model.val(data=DATASET_YAML, conf=conf, verbose=False)
    # 看 mAP50 / Precision / Recall
```

| 调法         | 效果  | 适用                       |
| ------------ | ----- | -------------------------- |
| **降低**阈值 | 召回↑ | 工业「宁可多检、不可漏检」 |
| **提高**阈值 | 精度↑ | 要少误报                   |

口条：**基线 → 增强 → 更大 s+1280 → 离线扩盘 → TTA → 扫 conf；漏检敏感就降阈值。**

## 评估指标

口述：工业质检看四个数——**mAP50（主指标）**、mAP50-95（竞赛向）、**Precision（控误报）**、**Recall（控漏检）**。业务上通常 **召回 > 精度**：漏检出事，误检只是多一次人工复核。

### 工业场景关注度

| 指标          | 含义                         | 工业关注度         |
| ------------- | ---------------------------- | ------------------ |
| **mAP50**     | IoU≥0.5 时的平均精度         | **高（主指标）**   |
| **mAP50-95**  | IoU 从 0.5～0.95 的 mAP 平均 | 中（竞赛常用）     |
| **Precision** | 报出的「缺陷」里真缺陷占比   | **高**（控误报）   |
| **Recall**    | 真实缺陷里被检出的占比       | **极高**（控漏检） |

口条：**宁可多检不可漏检 → 召回通常比精度更重要。**

### IoU（交并比）

判断检测框准不准：

```text
IoU = 预测框 ∩ 真实框 的面积 / 两者并集面积
```

| IoU | 含义       |
| --- | ---------- |
| 1.0 | 完全重合   |
| 0.5 | 重合约一半 |
| 0.0 | 完全不重合 |

规则：`IoU ≥ 阈值` → 算检测正确（**TP**），否则 **FP**。阈值越高，对定位越严。

### AP 与 mAP

| 概念    | 定义                                                         |
| ------- | ------------------------------------------------------------ |
| **AP**  | 单类在不同置信度下的 P-R 曲线下面积（AUC）；越高该类检得越准 |
| **mAP** | 各类 AP 取平均                                               |

钢铁六类示例：

```text
mAP = (AP_crazing + AP_inclusion + AP_pitted_surface + …) / 6
```

### mAP50 vs mAP50-95

| 指标         | IoU 阈值                        | 含义                                                   |
| ------------ | ------------------------------- | ------------------------------------------------------ |
| **mAP50**    | 固定 **0.5**                    | 框大致对上就算对；工业主看这个 → **能不能找到缺陷**    |
| **mAP50-95** | 0.5, 0.55, …, 0.95 共 10 档平均 | 从松到严；竞赛常用 → **定位精不精**（0.95 近乎像素级） |

一般 **mAP50 > mAP50-95**（高 IoU 很难达标）。

口条：**工业盯 mAP50 + Recall；IoU≥0.5 算找到；mAP50-95 才抠框精不精。**

## VLM 多模态方案：为什么要用 VLM？

口述：YOLO 强在**已知类框得准**，但新缺陷要重标重训、且**只报是什么/在哪、不说为什么**。VLM（如 Qwen-VL）补这三块：零样本、能解释、数据不够时先顶上。所以质检常是 **YOLO + VLM 双轨**，不是二选一。

### YOLO 的两个局限

| 局限             | 表现                                         |
| ---------------- | -------------------------------------------- |
| **要靠标注训练** | 新缺陷类型出现 → 采集 → 标注 → 重训，周期长  |
| **不能解释原因** | 只输出「是什么缺陷、在哪里」，说不清判定依据 |

### VLM 的独特价值

| 价值                | 说明                                         |
| ------------------- | -------------------------------------------- |
| **零样本识别**      | 不必先有训练数据；改 **Prompt** 就能认新缺陷 |
| **自然语言解释**    | 描述缺陷特征，给出判断逻辑（可审核、可追溯） |
| **快速验证 / 顶岗** | 新品上线、训练数据不足时，先用 VLM 顶着      |

和本章挂钩：前面「钢铁质检技术栈」里 YOLO 做精定位，Qwen-VL 做零样本分析——正是这个分工。

口条：**YOLO 管已知精检；VLM 管新类、解释、数据荒顶岗。改 Prompt 比重训快。**

## Bad Case 如何用于训练？

口述：Bad Case = 人工审核标成 **误检（wrong）** 或 **漏检（missed）** 的记录。**不能直接扔进 YOLO 重训**，要先改标，再并入训练集。工作台闭环：检测 → 审核 → 导出 → 重标 → 合并 → 重训。

### 导出长什么样

```text
exports/bad_cases_20260314_170000/
├── images/          # 出错原图拷贝（0.jpg, 5.jpg …）
├── bad_cases.csv    # 汇总表
└── export_info.json # 统计：wrong / missed 各多少
```

`bad_cases.csv` 关键列：`image_name / model_type / review_status / review_note / detections …`

| 例    | review_status | review_note          | detections                     |
| ----- | ------------- | -------------------- | ------------------------------ |
| 0.jpg | **wrong**     | 左上角划痕误判为龟裂 | `[{"class_name":"crazing",…}]` |
| 5.jpg | **missed**    | 右下角划痕未检出     | `[]`                           |

### 回流训练流程（AI 质检工作台）

```text
模型检测 → 人工审核（误检/漏检）→ 导出 Bad Case
    → LabelImg 等重标 → 并入训练集 images/ + labels/
    → 重新训练
```

**漏检例：`5.jpg`**

1. 导出到 `images/5.jpg`。
2. LabelImg 标上漏掉的划痕 → 生成 YOLO 格式 `5.txt`，如：`3 0.45 0.72 0.30 0.05`（类 id=3 对应 scratches；后四项为归一化中心 x/y、宽高）。
3. `5.jpg` → 训练集 `images/`，`5.txt` → `labels/`。
4. 重训：

```bash
python train_and_predict.py --device 0 --epochs 100
```

口条：**Bad Case 先导出再人工改标，再并集重训；误检改类/删框，漏检补框。**

## 工业缺陷检测的痛点是什么？

口述：最大痛点不是「第一次训不出来」，而是 **模型上线后性能会逐渐衰减**——产线在变，模型不跟着变就会掉点。

**衰减从哪来**

| 原因               | 例子                     |
| ------------------ | ------------------------ |
| **产线环境变化**   | 光照、材料批次、设备老化 |
| **新缺陷类型出现** | 训练集里没见过的类       |
| **边缘 case 积累** | 难例、罕见形态越积越多   |

应对思路：别指望一次训完；用 **Bad Case 驱动迭代** 把线上错误持续喂回训练。

### Bad Case 驱动的迭代流程

```text
【日常检测】                         【模型迭代】
YOLO 推理(~10ms/图)
  ├─ 正常 → 放行
  └─ 缺陷 → 告警
        ↓
  质检员确认
  ├─ wrong 误检 ─┐
  ├─ missed 漏检 ┼→ Bad Case 库(SQLite)
  └─ correct     │      ↓ 周/月导出
                 │  Export → bad_cases.csv + 图片
                 │      ↓
                 │  LabelImg 改标
                 │      ↓
                 │  并入训练集（新旧合并）
                 │      ↓
                 │  AutoDL GPU: train_and_predict.py
                 │      ↓
                 │  对比评估（含 Bad Case 修复率）
                 │      ├─ 变好 → 上线 best_v2.pt 替换线上
                 │      └─ 不行 → 加数据 / 调参，再训
```

和上一节衔接：导出格式、改标、重训命令就是这条闭环里的落地步骤。

口条：**痛点是上线后衰减；解法是 Bad Case 闭环——审核入库、改标并集、对比修复率再上线。**

## 不同阶段的模型迭代频率是怎样的？

口述：迭代别一刀切——**上线初期勤一点，稳定期拉长，新缺陷类型立刻动**。看频率，也看 Bad Case 攒够没有。

| 阶段               | 迭代频率         | 触发条件                                 |
| ------------------ | ---------------- | ---------------------------------------- |
| **新产线上线初期** | 每 **1～2 周**   | 累计 Bad Case 图 **> 50** 张             |
| **产线稳定运行**   | 每 **1～3 个月** | Bad Case **> 200** 张，**或** 漏检率上升 |
| **发现新缺陷类型** | **立即**         | 训练集里没有的新缺陷类出现               |

口条：**初期 1～2 周一迭代（>50 张）；稳定 1～3 月（>200 或漏检升）；新类立刻训。**
