# Agent 重点问题

> 先练这 12 道。每题口述 60–90 秒，最后一定带一句边界。关键词已经加粗。

## 1. 为什么用 LangGraph / Agent，而不是固定流程或一条链？

**答法**：固定流程要求执行前把顺序写死。江中很多请求的下一步取决于用户要做哪几件事、上一步查到了什么，整条路径写不出来。所以用 **classify → route → act**：模型只负责理解与提议，程序负责计划校验、工具执行和结算。固定业务仍然编译成子图，不是所有请求都进 Agent。

**关键词**：Agent 适用边界、固定流程、状态图、模型提议 / 程序结算。

## 2. `classify → route → act` 分别做什么？

**答法**：**classify** 判断意图类别；**route** 产出目标和结构化计划；**act** 按计划执行。只读查询走计划执行器，固定业务走子图，写操作进入审批。每步都有上限：计划最多 **8 步 / 3 层依赖**，每批最多 **3 个**并行。

**关键词**：意图分类、目标、结构化计划、计划执行器、并行上限。

## 3. 计划编译器校验什么？怎么防止乱跑？

**答法**：编译器校验 **工具是否已注册、参数是否符合 Schema、依赖是否成环、是否越过写边界**。目录外工具直接拒绝；缺参先问，不猜；只读失败可重试，写操作不自动重试。模型只能提议，执行权在程序。

**关键词**：计划编译、工具白名单、JSON Schema、依赖校验、写边界。

## 4. MCP 工具目录怎么用？参数怎么校验？

**答法**：宿主或中台每轮上报工具目录，模型只看到本次目录。参数用 **JSON Schema / Ajv** 运行时校验；参数错误最多修两次，不能借机换工具。越权在调用前拦，工具返回里的注入指令不执行。

**关键词**：MCP、动态目录、运行时校验、Ajv、参数绑定、注入。

## 5. 写操作为什么必须人工确认？怎么幂等？

**答法**：写操作走 **提议 → 审批 → 执行**。确认幂等并写审计；重复点击不会重复下单 / 派工。状态不明时拒绝自动重放，要求人工核对。

**关键词**：approval、幂等、审计、状态不明、不重放。

## 6. 会话、图状态、审批、场景回执怎么存？重启怎么恢复？

**答法**：会话、图状态、任务卡、审批和场景回执存 **PostgreSQL**；同一会话用**咨询锁**串行。恢复时读取已完成结果引用，**工单查询不会重跑**；状态不明只核对，不重放。

**关键词**：checkpoint、PostgreSQL、会话锁、结果引用、恢复。

## 7. 三维动作怎么保证真的执行了？

**答法**：服务端只生成 `name + params` 的动作；宿主执行后回传 **SceneReceipt**。没有回执不算成功；SSE 上的“正在定位”只是进度，不是执行结果。真正改变场景的只有聚焦、飞行、告警高亮，其余标记为模拟。

**关键词**：scene receipt、宿主执行、回执、simulated、SSE 进度。

## 8. Agent 怎么评测？

**答法**：**L1** 是固定断言：执行结果、安全拦截、数值溯源；**L2** 看完成率、工具成功率、完整交付率。再加裁判、人工标注、归因校准和回归草稿；不达线阻断发布。

**关键词**：L1 / L2、交付判定、裁判、人工标注、门禁。

## 9. 流量涨 10 倍，哪里先崩？

**答法**：先看**进程内限流**、**会话锁**、**SSE 连接**、**模型网关排队**、**向量检索**和**成本**。多实例要外置限流和状态；会话要能分片；SSE 要考虑粘性。先盯 P95、首字延迟、排队时间、工具失败率和单轮成本。

**关键词**：限流、会话分片、SSE 粘性、排队、P95、成本。

## 10. 哪些真正生效，哪些是模拟？怎么反驳“只是套了 LangGraph”？

**答法**：三维只有 3 个方法真正改变场景，其余标记模拟；微调和分布式没有生产验证。反驳点不是“我用了 LangGraph”，而是**计划编译器、参数校验、审批幂等、场景回执、评测门禁**这些框架不自带、自己补的工程。

**关键词**：真实生效、模拟、边界、计划编译器、回执、门禁。

## 11. 讲一个失败复盘。

**答法**：按 **现象 → 证据 → 哪一层 → 改了什么 → 怎么复验**。例如：设备存在但无告警，用户仍要定位；或目标类召回了却没进入最终上下文。先说看到了什么证据，再说根因和复验，不要归因于“模型不稳定”。

**关键词**：复盘、证据链、根因、复验。

## 12. 你的项目最大的技术难点是什么？

**答法**：不是“调通模型”，而是**让模型提议可控**：计划要能校验、工具要能绑定、写操作要审批、状态要能恢复、结果要能回执、改动要能回归。把这几件事拆开，每件都能落到代码和数字。

**关键词**：可控性、边界、状态、回执、回归。

## 项目中可能问到的关键词

- **classify / route / act**：意图分类、目标与计划、执行。
- **plan_step / plan_join**：只读计划的分批执行与依赖汇总。
- **计划编译器**：工具、参数、依赖、写边界校验。
- **MCP**：工具目录动态发现；服务端是调用方，编辑器是提供方。
- **JSON Schema / Ajv**：运行时参数校验。
- **approval / idempotency**：写操作人工确认、幂等、审计。
- **scene receipt**：宿主执行回执；没有回执不算成功。
- **PostgreSQL checkpoint**：会话、图状态、任务卡、审批、回执持久化。
- **L1 / L2 / gate**：固定断言、完成率与质量、发布门禁。
- **trace / Prometheus**：调用链和指标，用于定位退化。
- **RRF / parent block / evidence**：RAG 的融合、父块回填、证据守卫。
