# 江中智能助手 · 审阅台与可观测
> 用请求 ID 串起阶段、节点、工具、模型输入输出和证据，回答「这次为什么这么答、最早在哪一步偏离」。

## 目标

回答五个问题：

1. 这次请求走了哪些阶段、节点、工具，花了多久？
2. 模型看到了什么、返回了什么、证据在哪里？
3. 失败发生在哪一层，最早偏离在哪一步？
4. 这次评测批次的执行与交付结果如何，和上一批比变了什么？
5. 人工怎么判、裁判和人工是否一致、哪些问题能沉淀成回归题？

## 采集开关

```dotenv
TRACE_ENABLED=true
TRACE_TENANT=demo
TRACE_REVIEW_TOKEN=             # 可选；不配置时仅本机/白名单
TRACE_REVIEW_ALLOW_IPS=127.0.0.1,::1
TRACE_REVIEW_REVIEWER=local
TRACE_REVIEW_ALLOW_REVIEWER_HEADER=false
```

- 采集关闭时，审阅接口返回 503，主服务不受影响。
- 初始化失败不会阻止助手启动；后台每 30s 尝试恢复。
- 记录器有熔断：持续失败时暂停写入，恢复后探测。
- reviewer 默认取服务端配置；只有显式开启时才信任 `x-review-reviewer` 请求头。

## 数据模型

| 表 | 内容 |
| --- | --- |
| `review_runs` | 一次工作流/回合运行 |
| `review_turns`、`review_run_turns` | 回合与运行关联 |
| `review_steps` | 业务步骤 |
| `review_segments` | 一次请求内的分段 |
| `review_spans` | 模型、工具、场景、审批、decision、回复等节点 |
| `review_bodies` | 大正文，按预算去重/截断 |
| `review_access_audit` | 审阅访问审计 |
| `review_annotations` | 人工标注：四类检查、逐节点、最早偏离、责任 span、证据、解决方案 |

审阅契约由 `apps/server/src/review/contract.ts` 拥有；审阅台维护自己的响应投影，不再依赖共享包。

## 可观测的阶段

| 阶段 | 记录 |
| --- | --- |
| 请求分类 | `model` span，displayName「请求分类」 |
| 任务规划 | `model` span，displayName「任务规划」 |
| 执行/答复 | `model` span、`tool` span、`reply` span |
| 调度决策 | `decision` span：来源、规则、命中词、decisionType、步骤 |
| 计划步骤 | `step` / `tool` / `decision` 组合，含依赖、跳过、阻塞原因 |
| 审批/场景 | `approval` / `scene` span，等待状态与回执 |
| 交付判定 | 评测产物中的 `delivery`、`judge`、`outcome` |

- 时间线和详情在「调度决策」后显示阶段备注：路由规划、执行器接管、分支分发、选择步骤、分支汇聚。
- 未知 `decisionType` 原样显示，不做猜测。
- 静态检查拦截新增中文业务正则，防止控制流退回关键词判断。

## 脱敏与预算

- 环境变量中配置的密钥会在写入前替换为标记。
- 正文按大小预算截断，超限显示「证据因链路正文预算被省略」。
- 访问审计记录谁在什么时候查了哪条链路。
- 评测报告与标注接口只读文件或数据库，不执行任意脚本。

## 审阅 API

统一前缀 `/v1/review`，复用审阅 token/IP 鉴权。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/runs` | 链路列表；支持关键词、流程、状态、会话、来源、评测批次、时间、游标 |
| GET | `/runs/:id` | 链路详情 |
| GET | `/runs/:id/export` | 导出证据正文 |
| GET | `/eval/history` | 评测历史趋势 |
| GET | `/eval/cases` | 评测题库 |
| GET | `/eval/batches` | 评测批次列表 |
| GET | `/eval/batches/:batchId` | 批次详情与变量指纹 |
| GET | `/eval/batches/:batchId/cases/:caseId` | 逐题详情、交付、裁判、证据 |
| POST | `/eval/rejudge` | 用保存的答案/证据重评裁判，不重跑助手 |
| POST | `/eval/runs` | 发起评测任务 |
| GET | `/eval/runs/:id` | 查询评测任务 |
| GET | `/annotations` | 当前 reviewer 的标注列表 |
| GET | `/annotations/items` | 分页标注 |
| GET | `/annotations/summary` | 标注汇总与逐条明细 |
| GET | `/annotations/config` | reviewer 与请求头开关 |
| GET | `/annotations/export` | 导出标注 |
| POST | `/annotations/import` | 导入标注 |
| GET | `/annotations/attribution` | 最早偏离/责任节点归因 |
| GET | `/annotations/calibration` | 人工 vs 裁判一致率与分歧 |
| GET | `/annotations/regression` | 回归草稿列表 |
| POST | `/annotations/regression` | 从标注生成回归草稿 |
| POST | `/annotations/regression/:id/confirm` | 确认草稿为 ready |
| GET | `/annotations/:workflowRunId` | 单条标注 |
| PUT | `/annotations/:workflowRunId` | 保存草稿或提交 |

## 审阅台

地址 `http://127.0.0.1:7776`。

### 六个工作区

| 工作区 | 内容 |
| --- | --- |
| 在线对话 | 业务链路列表、详情、导出、证据、影响步骤 |
| 评测题库 | 按读取/写入/其他分类的题目，选择后一键运行 |
| 评测历史 | 批次表、逐题结果、链路跳转、两批次对比 |
| 评测总览 | 执行、裁判、人工三组指标；历史趋势；交付质量卡片 |
| 标注汇总 | 概况、四类覆盖、最早偏离、逐节点统计；左右分栏逐条工作区 |
| 归因校准 | 归因分布、人工 vs 裁判一致率、分歧回链、回归草稿 |

### 链路详情

- 节点树、耗时、输入/输出、证据路径、影响步骤。
- 详情页签：执行链路、模型、工具、回复、原始。
- 在线记录只显示业务 refs；评测记录额外显示批次、用例、分类。
- 「人工标注」按钮从右侧展开 `el-drawer`，不挤占主区；支持草稿恢复、提交、保存并到下一条未标注。
- 标注抽屉并排显示参考标准与实际结果：事实表、参考计划、精度、逐节点参考请求/结果。

### 标注汇总

- 顶部显示概况与结论；
- 下方左右分栏：左栏可搜索、按状态/判定筛选、独立滚动；右栏显示具体问题、四类检查、拆解/节点表、问题描述、解决方案与验证方式、证据、参考标准与元信息；
- 每条提供「打开标注」「查看链路」；
- 正式通过率只统计 `status=submitted`，草稿只计入草稿数。

## 请求观测

- 每个响应带 `X-Request-Id`；合法入站值沿用。
- 访问日志一行 JSON：`event=http_request`、方法、路径、状态、耗时、请求 ID。
- 轮次完成日志：`event=turn_completed`、turnId、workflowRunId、状态、模型/工具调用数、耗时。
- 工具日志：`event=tool_call`、工具、code、attempts、耗时。
- 规划日志：`event=route_parse`，包含 taskIntent、execution、plan、dropped。
- 错误响应统一 `{error, requestId}`，不含堆栈。

## 已知限制

- 审阅台没有完整自动化 UI 测试，靠接口测试、Playwright 冒烟与手工验收。
- 采集默认关闭；演示前要显式打开 `TRACE_ENABLED=true` 并重启。
- 多副本写同一租户时以数据库为准，审阅台只读。
- 标注首版按 `(tenant, workflowRunId, reviewer)` 唯一键覆盖，不做多人投票/合并。
- 校准首版只比较交付判定，不把四类检查全部映射成一致率；校准结果不进入 gate。
