# 江中智能助手 · 场景与宿主前端
> 服务端不内置三维能力：宿主注册场景方法、上报目录、执行动作并回执；可移植对话模块按 core / ui / 业务适配三层拆开。

## 没有独立 SDK

当前仓库已经**没有独立 SDK**。`packages/assistant-sdk` 在 `cross/S057` 中撤销，可移植部分收进 `examples/host-demo/src/assistant/`。共享的 `trace-contract` 也在 `cross/S058` 中撤销，审阅契约由网关拥有。

## 场景方法从哪里来

服务端**不内置**三维方法。宿主通过 `registerScene(name, handler, registration)` 声明名称、用途与参数 Schema；宿主模块在每次 `/chat`、`/chat/stream`、`/scene/receipt`、`/approval/decision` 上报 `sceneCatalog`。模型只看到本次上报的目录。

Demo 的目录在 `examples/host-demo/src/tools/catalog.ts`，共 **26 个方法**。

## 场景里的设备标牌

每个盒子顶部有一个 `THING.HTMLMarker`，显示设备 ID 与名称（`SANC01`、`SANC03`、`EXTR04`）。标牌跟随设备、始终面向相机；高度按设备错开，避免默认视角下重叠。对话发送「飞到 3 号设备」时，相机真实移动，执行记录显示「视角飞行 / 成功 / 三维生效」。

## 设备与演示业务

| 设备 | 主业务 | 示例 |
| --- | --- | --- |
| SANC01 | 故障报修 → 维修工单 | 「SANC01 压片机主轴异响故障，帮我报修」 |
| SANC03 | 告警处置 → 取消告警 | 「SANC03 温度偏高告警，帮我取消告警」 |
| EXTR04 | 批次追溯 → 提取工序 | 「批次追溯」→「B20260001」→「正向」 |

普通告警不等于故障：只有故障/报修才创建维修工单；普通告警优先取消。

助手回复使用 `markdown-it` 渲染：标题、列表、代码块、表格和链接可读；原始 HTML 被禁用，链接在新窗口打开。

## [重点] 哪些方法真的改变场景

| 方法 | 效果 | 记录 |
| --- | --- | --- |
| `focus_device` | 相机聚焦设备 | 三维生效 |
| `fly_to_device` | 相机飞向设备 | 三维生效 |
| `highlight_alarm` | 材质变红/橙/黄并脉冲 | 三维生效 |
| 其余 23 个 | 只返回 `simulated: true` | 仅模拟 |

宿主日志按方法判定，不伪装成功；失败会显示错误原因。

## 执行回执语义

```ts
type SceneReceipt = {
  id: string
  success: boolean
  simulated?: boolean
  error?: string
}
```

- `pending=true` 的动作由宿主执行，成功后 `POST /scene/receipt`，服务端继续。
- 流程回合的即时动作（`pending=false`）由宿主模块直接执行，不回执、不写服务端日志，失败只回调并告警。
- 执行前写 `started`；状态不明时要求人工核对，不自动重放。
- 回执提交失败：调用 `retrySceneReceipt()`，不要再次执行动作。

## [重点] 宿主对话模块的三层

| 层 | 目录 | 统一什么 | 换项目时改什么 |
| --- | --- | --- | --- |
| 对话核心 | `examples/host-demo/src/assistant/core/` | HTTP/SSE、会话、审批提交、场景回执、恢复、幂等 | 不改 |
| 对话窗口 | `examples/host-demo/src/assistant/ui/` | 消息列表、流式、审批容器、输入框、错误/重试 | 可换样式或 UI 库 |
| 业务适配 | 宿主 `src/integrations/` | 审批输入解释、审批卡、场景执行、文案 | 必改 |

硬约束：

- `core/` 不 import Vue、Element Plus、ThingJS 或任何业务文件；
- `ui/` 允许 Vue 与 Element Plus，但不写业务判断；
- 审批卡只产出 patch，不自己调用 `/approval/decision`；
- 待审批期间的输入解释放在 `ApprovalAdapter.interceptPendingInput`；
- 未注册渲染器的审批显示「宿主暂不支持」，隐藏确认按钮。

验证：

```bash
pnpm --filter @jiangzhong/demo test
pnpm --filter @jiangzhong/demo typecheck
pnpm --filter @jiangzhong/demo build
```

`test/purity.test.js` 静态检查 `core/` 不含 Vue、Element Plus、ThingJS 或江中业务；`test/replacement.test.js` 用假网关、假审批和假场景验证窗口可移植。

## 审批卡与报修弹窗

维修审批卡只读显示当前告警与描述；点「放大」打开 body 下居中的工单弹窗，除设备 ID/告警外可编辑标题、描述、故障类型、紧急程度、停机、报修人、电话、期望时间，支持全屏。也可以在输入框发「报修描述填写为：…」更新描述。

处理参考折叠展示，只作提示，不写入工单。字段清单与真实 CMMS 的差距见 [/03-项目实战/02-江中智能助手/03-三条业务流程](/03-项目实战/02-江中智能助手/03-三条业务流程)。

## [重点] 为什么有 `fetch` 注入

ThingJS 2.0 会用 XHR polyfill 覆盖全局 `fetch`，返回对象的 `body` 不是 `ReadableStream`，模块的 `stream()` 会报 `getReader is not a function`。

处理方式：

- `index.html` 在 ThingJS 脚本之前保存 `window.__nativeFetch`；
- `GatewayClient` 支持 `fetch` 选项，Demo 注入原生实现；
- `stream()` 遇到 `body` 无 `getReader` 时抛可读的 `AssistantError`。

契约见 `specs/cross/S008-sdk-fetch-injection.md`。

## Demo 宿主

- 全屏 ThingJS 场景；聊天固定在左下，执行记录固定在右上。
- 执行记录显示时间、来源（对话/调试）、方法中文名与英文名、参数、成功/失败、三维生效/仅模拟。
- 场景调试可直接选方法、改 JSON 参数执行，用来验证宿主是否接通。
- ThingJS 登录失败或 WebGL 不可用时，场景显示错误，聊天与记录仍可用。

## 为什么撤销独立 SDK

- 该包只服务一个宿主、为 `private` 且未发布；
- 审批输入解释和工单字段组装仍在宿主，单独换 SDK 不足以移植；
- 不同宿主的 UI、身份、三维场景差异大，收进宿主模块更容易整体复制；
- 网关仍是唯一事实源，HTTP/SSE 合同不变。

## 已知限制

- 本地库 + 程序化 3 个盒子；正式登录后的完整园区资源包未验证。
- 26 个方法中只有 3 个真正改变画面；其余是接口演示。
- 执行记录只在当前页面内存与 `sessionStorage`，不持久化、不上报审阅台。
- 宿主模块没有 npm 发布、tarball 或模板；迁移时复制目录并替换业务适配器。
