# 江中智能助手 · 会话、记忆与身份
> 会话如何串行、持久化和恢复；无登录 3D 宿主如何区分「我」；长期记忆如何按范围隔离、事件写入、过滤召回。

## 会话生命周期

| 操作 | 行为 |
| --- | --- |
| `POST /v1/conversations` | 新建会话，返回 `sessionId`、状态、过期时间 |
| `GET /v1/conversations/:id` | 按当前用户/租户查询；越权、缺失、过期统一 404 |
| 旧客户端 `POST /chat` | 不带会话时自动建 |
| 过期 | 最后更新后 7 天；每小时清理 |
| 新会话 | 宿主模块 `newSession()` 清空本地场景日志并换新 `sessionId` |
| 放弃中断轮次 | `POST /v1/conversations/:id/abandon-turn` |

## 并发控制与轮次租约

- 同一会话的轮次通过 PostgreSQL 咨询锁串行，跨实例有效。
- 等待上限 `SESSION_LOCK_TIMEOUT_MS`（默认 10s）；超时返回 409 `session_busy`。
- 过期会话返回 409 `session_expired`；客户端应新建会话而不是重试。
- 多副本时数据库是唯一协调点，进程内没有会话锁。

| 字段/机制 | 说明 |
| --- | --- |
| `active_turn_id` | 当前正在处理的轮次 |
| `heartbeat_at` | 心跳时间，默认每 10s 更新 |
| `lease_owner` | 持有租约的进程标识 |
| `interrupted_at` | 中断时间；中断轮次需放弃后才能继续 |
| `last_turn_id` | 最近一轮，便于恢复 |

- 正常结束调用 `finishTurn`；异常调用 `interruptTurn`；用户主动放弃调用 `abandonTurn`。
- 预算错误且尚未发生工具副作用时，会话直接恢复 ready，不永久锁成 interrupted。
- 相同 `messageId` 的消息走消息级幂等：已完成重放结果，处理中返回 409，内容不同返回冲突。

## 持久化内容

| 数据 | 位置 | 生命周期 |
| --- | --- | --- |
| 会话元数据 | `assistant_sessions` | 7 天未更新过期 |
| 图状态/消息 | LangGraph `PostgresSaver` checkpoint | 随会话；用于恢复与待办 |
| 消息幂等 | `assistant_message_receipts` | 24h 未更新清理 |
| 审批审计 | `assistant_approval_audit` | 记录提议、决策、执行结果 |
| 请求幂等 | `assistant_idempotency` | 默认 24h |
| Dify chat 会话 | `assistant_dify` | 随会话 |
| 后台运行 | `assistant_runs` | 结果与状态持久化；重启不重跑 |
| 长期记忆 | `assistant_memory_*` 五表 | 默认 30 天；job 成功 7 天、dead 30 天 |
| 场景回执日志 | 浏览器 `sessionStorage` | 键 `assistant-scene:<sessionId>` |
| 执行链路 | `review_*` | 可配置保留与清理 |
| 人工标注 | `review_annotations` | 按 reviewer 唯一键保存 |

## 上下文预算与摘要

长会话按 token 预算而不是消息条数处理（默认值）：

| 预算 | 默认值 |
| --- | --- |
| 普通输入 | 10,000 |
| 知识库输入 | 30,000 |
| 输出预留 | 2,000 |
| 安全余量 | 1,000 |
| 最近对话 | 6,000 |
| 摘要 | 2,000 |
| 单条工具结果 | 800 |

- 估算输入超过预算时触发压缩。
- 主模型只接收「系统提示 + 任务卡 + 记忆 + 结构化摘要 + 预算内最近轮次」。
- 当前轮完整保留；较早轮次的工具结果先压缩。
- 最近窗口按完整轮次向前扩展，不拆散 tool_call / tool_result。
- 摘要要求模型输出目标/事实/动作/失败/未完成/约束的 JSON；解析失败保留纯文本，摘要失败保留旧摘要，不阻塞本轮。
- 请求冻结时 total 只计一次 system（已含摘要/记忆），避免重复计数。

`AssistantState.summary`、`summaryCount` 和 `taskCard` 随 checkpoint 持久化，但都不是长期 memory；完整原始消息仍保留在 checkpoint 中，由 7 天清理任务删除。

## 后台运行（`/v1/runs`）

```text
POST /v1/runs { sessionId, message, messageId? }
  → 写 assistant_runs（queued）
  → 返回 202 { run }
  → RunWorker 每 1s 领取 queued，租约 30s，心跳 10s
  → 复用 assistant.send 执行
  → succeeded / failed / cancelled 写回 result
```

- 单进程 worker；启动时把遗留 running 标为 failed，不自动重跑。
- 取消：`POST /v1/runs/:id/cancel` 先标 `cancel_requested`，worker 心跳发现后 abort。
- 同 `messageId` 重复创建会返回已有运行。
- 后台运行仍受会话串行、预算、审批和工具合同约束。

## 幂等

- 仅已认证的 POST 支持 `Idempotency-Key`；`/chat/stream` 不支持。
- 相同键 + 相同请求体：24h 内重放首次响应，带 `Idempotent-Replayed: true`。
- 相同键 + 不同请求体：409。
- 消息级幂等用 `messageId`，由 `assistant_message_receipts` 记录。
- 记录存 PostgreSQL，可多副本共享；过期由每小时清理任务处理。

## 场景回执与「状态不明」

宿主模块在执行前写入 `started:true`，执行后写成功/失败。若请求中断、进程重启或页面刷新导致只有 `started`：

- `recoverSession()` 会拿到待办；
- 对状态不明的动作，模块生成失败回执「此前执行状态不明，请人工核对」；
- 不会自动重放，避免重复创建工单、重复取消告警等副作用。

回执字段、`simulated` 语义和 `retrySceneReceipt()` 的处理见 [/03-项目实战/02-江中智能助手/05-场景与宿主前端](/03-项目实战/02-江中智能助手/05-场景与宿主前端)。

## 安全边界

- 令牌只从环境变量读取，不在代码、日志、测试 fixture 中出现。
- 审阅正文按密钥列表脱敏；请求日志只记方法与状态，不记 body。
- 写操作必须人工确认；确认步不接受模型兜底。
- 演示写操作只允许指向本机 mock（`ZHONGTAI_DEMO_WRITE_ENABLED` + `127.0.0.1:7779` 校验）。
- 生产环境禁止 `AUTH_MODE=off` 与 `LOCAL_LOGIN_ENABLED=true`。

## [重点] 无登录宿主的身份设计

> 场景：助手嵌在 3D 系统里，3D 系统没有登录页。那「我的报修」怎么知道「我」是谁？新会话会不会丢？

### 三个 ID 要分开

| ID | 含义 | 生命周期 | 用途 |
| --- | --- | --- | --- |
| `sessionId` | 一次对话线程 | 新建会话/过期 | LangGraph checkpoint、消息历史 |
| `userId` | 当前操作人/终端 | 跨会话稳定 | 报修归属、权限、审计 |
| `clientId` | 浏览器/终端标识 | 设备本地持久 | 无登录时的兜底身份 |

**不能用 `sessionId` 当用户 ID**：新建会话会变，报修就丢了。

### 当前 demo 的真实情况

- demo 使用固定 token，服务端解析出 `userId=demo`。
- `query_my_work_orders` 查的是 `work_order_operation.user_id=demo`，**不是 sessionId**。
- 所以新建会话只换 `sessionId`，**工单不会丢**；同一 token 下仍能查到。
- 但所有使用该 token 的窗口都是 `demo`，多人共用会互相看到，这不是真正的「我的」。

### 三种可选方案

**方案 A：3D 宿主注入操作人身份（推荐，如果宿主知道当前操作人）**

- 宿主登录/工牌/班组系统给出 `operatorId`；
- 宿主向后端换取短期 token，或传签名身份头；
- 服务端 `AUTH_USERS_JSON` / 身份服务把它映射成 `userId`；
- 报修归属到真实操作人，跨会话可追踪。

不要在请求体里直接传一个未签名的 `userId`，否则谁都能伪造。

**方案 B：终端身份（宿主不知道人，只知道这台中控机）**

- 给每台中控机配置 `terminalId`，例如 `console-01`；
- 服务端把 `terminalId` 当 `userId`；
- 界面文案叫「本机报修」，不是「我的报修」；
- 跨会话稳定，适合交接班/共享终端。

**方案 C：浏览器本地 clientId（仅 demo）**

- localStorage 生成 `host-demo-client-id`；
- 宿主对话模块 `GatewayClient` 请求带上；
- 只能做演示，清缓存/换浏览器就丢，且可伪造。

### 推荐与不要做

- 如果 3D 系统能拿到当前操作人：用方案 A，报修归属到人。
- 如果只有中控机：用方案 B，文案改「本机报修」。
- 当前 demo：仍可用 `AUTH_DISABLED=true` 公共模式做演示；生产接入时切换为方案 A。
- 如果宿主在打开 3D 前已经完成登录：优先方案 A，由宿主后端签发短期 token，宿主对话模块的 `GatewayClient` 从宿主全局上下文取 token，服务端校验后再写入任务卡 actor；不要把未签名的 userId 放在请求体里。

不要做：

- 不要把 `sessionId` 存进工单归属。
- 不要用 localStorage 当作生产身份。
- 不要在客户端直接声明 `userId` 而不做服务端校验。

### 不同电脑时 token 怎么发

结论：**每台电脑在部署时配置自己的 token，不是用户登录后领取。**

```text
电脑 A（中控台 01） → token-A → userId=console-01
电脑 B（中控台 02） → token-B → userId=console-02
电脑 C（中控台 03） → token-C → userId=console-03
```

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| 部署配置 | 安装包/部署脚本把 token 写入该机 3D 宿主配置或环境变量 | 最常见 |
| 宿主后台签发 | 3D 后端用服务凭证 + 机器证书/主机名换短期 token | 有宿主后端 |
| 管理员手工配置 | 运维把 token 写入本机配置文件 | 小规模 |

身份粒度：

- **一台电脑一个人**：终端 token 实际等价于这个人，够用。
- **一台电脑多人共用**：只能识别到电脑，界面叫「本机报修」。
- **要跨电脑按人追踪**：必须由 3D 宿主提供操作人身份（工牌/班组/已有账号），走方案 A。

不要让用户手输 token：没有登录页时，token 属于设备配置，不是用户输入。用户手输 token 既不方便，也会让 token 在人群里传播。

安全边界：

- 每台机器一个 token，可单独吊销；
- 使用短期 token 或宿主后端代理，避免浏览器里长期 token 被复制；
- 不要把同一个长期 token 发给所有电脑。

## [重点] 分层记忆落地

> 参考课程《分层记忆管理》的「短期/长期按复用范围分、业务状态以业务系统为准、提取—对照—保存—召回—选择—预算—回答」闭环。

默认关闭：`MEMORY_ENABLED` 未设置时，服务启动不会初始化记忆库与 worker；开启后初始化失败只关闭记忆召回，不阻止助手启动。

### P0：token 预算上下文

- 文件：`apps/server/src/agent/context/{context,tokens,tool-compaction}.ts`
- 预算默认值与压缩规则见上文「上下文预算与摘要」。
- 当前轮完整保留；较早工具结果先压缩；最近窗口按完整轮次扩展。
- 摘要为 JSON：`objective / facts / actions / failures / pending / constraints`。
- 失败降级：摘要失败保留旧摘要；解析失败保留纯文本；预算错误且无工具副作用时恢复 ready。

### P1：任务卡与身份

- 文件：`apps/server/src/agent/planning/task-card.ts`
- `AssistantState.taskCard` 随 checkpoint 持久化。
- 字段：actor、goals、plan、steps、observations、receipts、deviceIds、alarmCodes、workOrderCodes、batchNos、workflowKind/step、pendingApproval、constraints、confirmedFacts、unknowns、taskStatus、waitingFor。
- actor 只从服务端已验证 `Identity` 取；不支持请求体自报 userId。
- 任务卡以紧凑文本进入系统提示词，不包含工具结果原文。
- 同会话只读任务续接（S061）：等待补参、计划修订、设备纠正、证据时效、重复提交、新问题打断。

### P2：长期记忆数据模型与写入

| 表 | 作用 |
| --- | --- |
| `assistant_memory_profile` | 已知字段，按 key 直接读；active/superseded/deferred |
| `assistant_memory_record` | 开放式语义/经历/程序性记忆 |
| `assistant_memory_source` | 原话、消息、工具调用来源 |
| `assistant_memory_audit` | add/update/confirm/defer/delete 审计与前后快照 |
| `assistant_memory_job` | 事件驱动的异步提取队列 |

范围：`device / line / workshop / shift / user`，按 `tenant + scope_type + scope_id` 隔离。约束写在 DDL 的 CHECK 约束里，不靠模型自觉。

写入管线：

```text
业务事件（报修成功、告警确认/关闭、巡检异常、备件申请、交接班、用户明确更正/记住）
  → MemoryWriter.enqueue：写 assistant_memory_job（queued）
  → worker 每 1s 领取（FOR UPDATE SKIP LOCKED）
  → 模型提取 JSON：profile_updates / records / unresolved
  → 程序校验：quote 必须是本轮原话子串；字段与操作合法；记录属于当前 tenant + scope
  → 事务内 add/update/confirm/defer + 审计
  → completeJob；失败重试，超过上限置 dead
```

- 不是每轮提取；只在事件后触发。
- 同一 `tenant + operation_id + event_type` 只入队一次。
- 模型不能生成 userId/tenant/来源 ID。
- 当前告警、工单、库存等业务状态不写入长期记忆。

### P3：召回、选择与注入

```text
问题 + 任务卡
  → 按 tenant/scope 过滤
  → profile 按 key 读取
  → record 走 FTS + 最近记录（候选上限 20，profile 上限 10）
  → 选择器逐条输出 use/reason，必须覆盖全部候选且理由非空
  → 只把选中的记忆放进上下文
  → 记忆预算默认 2000 token
  → 回答中的 [[mem:id]] 必须来自本次候选
```

- 候选为空时明确说「没有相关记忆」，不让模型编造。
- 记忆读取失败与「没有记忆」分开：失败标记 `unavailable`。
- 选择器输出非法（缺候选、重复 key、空理由）时整体回退为空选择，不猜。
- FTS：优先 `pg_jieba` 的 `jiebacfg`；扩展不可用时用 `simple`，不是语义向量检索。

### 冲突规则

| 情况 | 采用 | 记忆处理 |
| --- | --- | --- |
| 业务系统状态 vs 记忆 | 业务系统 | 记忆只作历史参考 |
| 本单要求 vs 长期默认 | 本单要求 | 长期默认保留 |
| 明确更正 vs 旧记录 | 更正后 | 旧记录 superseded，保留来源 |
| 两次相似事件 | 分别保留 | 不合并成一次 |
| 指向不清 | 暂不处理 | `defer` + 原因 |

### 评测、审计与保留

- 审计记录 actor、操作、前后快照；可按 tenant/scope 查。
- 默认保留 30 天（`MEMORY_RETENTION_DAYS`）；job 成功任务保留 7 天、dead 保留 30 天。
- 记忆黄金集与指标已有基础实现（S036），但尚未接入主评测门禁。
- 跨会话能查到同一设备的复发记录；用户 A/B 记忆互不可见；更正后旧记录 superseded。

### P4：还没做的部分

1. 用户域偏好：常用设备、常用查询；只存明确表达、可撤销的偏好。
2. 删除接口与隐私流程：按用户/设备删除、导出、保留期策略。
3. 记忆评测进入主看板：Recall@K、选择准确率、回答忠实度、Faithfulness。
4. 回放：同一初始快照，对比修改前后写入/召回/回答。
5. 向量检索：当前只有 FTS；需要语义召回时再评估，不先上向量库。
6. 跨会话任务找回：当前只支持同会话续接，不做跨会话找回。

### 建议顺序

```text
P4.1 用户域偏好与删除接口
  → P4.2 记忆评测指标进入总览
  → P4.3 回放与 red/green 对照
  → 需要时再评估向量检索
```

不要先做向量库，也不要在身份不可信时做个人记忆。先把「设备域记忆 + 来源 + 冲突 + 预算」跑稳，再扩范围。
