## 图中刻意标注的边界

- 并行召回是 **向量 + BM25**；精确符号召回用于融合后的置顶/补位，不是第三路并行。
- 显式类名/代码题把候选池扩到向量 56 / BM25 80；普通题仍是 28 / 28。
- `conflicts` 与 `minFusionScore` 是预留契约字段，当前检索链未生成。
- 限流是进程内；多实例需外置。
- 提示词不热更新，改 YAML 需重启。
- 索引不建 ANN，LanceDB 全表扫描约 90ms。
- 网关忽略 `max_tokens` 等输出上限；服务端用 `finish_reason=length` 和实际 `completionTokens` 后置校验。
- 生成门禁最新一次 23/24 被拦截；24/24、95.8% 是历史通过版本，不要混写。

## 10–12 分钟演示流程

主线：**用户问答 → 看引用/耗时/提示词 → 复杂/否定问题 → 贴代码+报错 → 点踩 → 观测台 trace/重放 → 问题队列 → 回归用例 → 单题验证 → 发布检查。**

### 录屏前准备

```bash
pnpm install
# 确认 server/.env 已有网关/模型/索引配置
pnpm dev
```

确认三个地址可打开：

| 服务 | 地址 |
| --- | --- |
| 前端问答 | http://127.0.0.1:9966 |
| 评测平台 | http://127.0.0.1:9968 |
| 服务端健康 | http://127.0.0.1:9967/api/health |

检查：

- `/api/health` 返回 `ok=true`、`indexReady=true`、`publish.status=ready`。
- 如果刚改过 `server/prompts/*.yaml` 或代码，**重启 `pnpm dev:server`**，否则 code-debug 提示词和消息字段不会生效。
- 如果 `WEB_AUTH_MODE=gateway`，准备一个演示账号；录制时不要录入真实密码。
- 评测平台可直接打开 `http://127.0.0.1:9968`；前端顶栏「观测」只对 `WEB_ADMIN_USERS` 显示，普通演示账号看不到也不影响录屏。
- 1920×1080，浏览器缩放 100%–110%，隐藏书签栏；只开 4 个标签页：前端问答、前端检索、`/calls`、`/release`。
- 清理通知和包含真实账号/密钥的窗口；录屏 30fps，鼠标移动慢一点，点击后停 1 秒再说话。

### 分镜

| 镜头 | 时长 | 操作 | 口播要点 |
| --- | --- | --- | --- |
| 1 开场 | 10s | 停在前端首页 | 「文档 RAG 问答，有引用、有置信度、可追踪、可回归」 |
| 2 登录/账号 | 20s | gateway 登录或 off 模式 | 「令牌只存服务端，浏览器只有 HttpOnly Cookie；侧栏看配额」 |
| 3 简单问答 | 60–90s | 问「THING.Box 怎么设置 width？」→ 查看依据/耗时/提示词 | 「回答不是黑盒；引用按正文重排，必须来自本次证据」 |
| 3B 示例代码路由 | 30–45s | 问「怎么动态修改对象的颜色和透明度？」 | 「demo-index 把业务意图和文件做路由，能命中设置样式.js」 |
| 3C 会话记忆 | 30–45s | 追问「那 height 呢？」→ 看调用详情 budgets | 「追问只带相关片段和最后一组问答；20 轮输入 -29.6%」 |

| 7 点踩→问题 | 45s | 点踩并提交评论 | 「点踩自动进问题队列，带 trace、分类，按指纹去重」 |
| 8 观测台+重放 | 60–90s | `/calls` 找调用→详情→重放 | 「trace/阶段/证据/prompt/usage；重放新 trace，不复制旧回答」 |
| 9 趋势 | 30s | `/trends` | 「调用/错误/空结果/点踩率/P95/索引版本」 |
| 10 问题队列+回归 | 90s | `/issues` 流转→生成回归用例 | 「状态受控；关闭前必须有回归用例和通过验证」 |

| 13 收尾 | 15s | 回到完整回答+引用 | 「能用、可解释、可回归、可发布」 |

## 3 分钟极简演示

只录这 5 步：

1. 简单问答 + 查看依据（40s）；
2. 否定/多类问题（30s）；
3. 贴代码 + 报错（50s）；
4. 点踩 → 问题队列（30s）；
5. 发布检查结论（20s）。

不要展开趋势、评测历史、重放；用口播一句带过「后台有完整观测和门禁」。

## 录屏注意事项与兜底

| 现象 | 原因 | 现场处理 |
| --- | --- | --- |
| `/api/health` 不是 ready | 索引/模型未加载 | 先启动服务；不要开始录 |
| 回答没有「结论 → 原因 → 修复 → 依据 → 验证边界」 | 服务端未重启 / 旧提示词 | 重启 `pnpm dev:server` 后重录该镜头 |
| 登录失败/配额不可用 | 网关不可用 | 切免登录模式或跳过登录镜头 |
| 点踩没有建问题 | 问题队列/数据库写失败 | 刷新问题队列；仍失败则跳过该镜头，口播说明 |
| 重放 409 | 旧调用没有 detail | 换最新一条调用 |
| 回归验证无可选问题 | 问题未进入待验证/无用例 | 展示已有运行记录，不现场造数据 |
| 发布检查 blocked | 门禁/问题/质量阈值未过 | 直接讲原因，不要强行改成 release |

录屏时不要展示：`server/.env`、任何 token / API Key / 密码；真实姓名、手机号、真实客户数据；原始 SQLite 文件、会话文件、服务端日志中的密钥或内部地址；未脱敏的内部文档路径；真实用户的问题队列内容。
