# THINGJS 文档 RAG · 项目全景与架构
> 一句话定位：把 ThingJS 官方文档变成可检索、可引用、可评测、可运维的 RAG 问答服务。

## 定位

ThingJS 是优诺的 3D 场景开发框架，文档里有大量类、成员、构造参数、示例和项目约定。开发者的问题通常长这样：

- 「THING.Box 怎么设置 width？」
- 「相机怎么飞到某个物体旁边？」
- 「同时创建多个 Box 和 Cylinder 怎么写？」
- 「不要用 Marker，怎么做标注？」
- 「这个报错/这个属性在文档里怎么说的？」

纯关键词搜索解决不了口语化、错拼、多类对比和否定约束；直接把文档丢给大模型又会编 API、编默认值、泄漏内部路径。项目要解决的就是三件事：**召回对、回答稳、质量能量化**。

## 项目边界

| 是 | 不是 |
| --- | --- |
| ThingJS 文档的检索与问答 | 通用聊天机器人 |
| 带引用、置信度、空结果原因的回答 | 只返回一段模型文本 |
| 文档变更后的索引热更新 | 每次请求现读 Markdown |
| 检索/生成/回归三套质量门禁 | 只靠人工“感觉还行” |
| Web、MCP、评测平台三个入口 | 只做一个页面 |

## 技术栈

### 服务端 `server/`（端口 9967）

| 能力 | 选型 | 版本/说明 |
| --- | --- | --- |
| 语言/运行时 | TypeScript + Node.js | TS 5.7，Node ≥ 22，ESM |
| Web 框架 | Express | 4.21 |
| RAG 核心 | LangChain JS | `langchain` 0.3.37，`@langchain/core` 0.3.80 |
| 模型接入 | `@langchain/openai` | 0.5.18，兼容 OpenAI 协议的网关 |
| 向量库 | LanceDB | `@lancedb/lancedb` 0.19 + `@langchain/community` 0.3.59 |
| 中文 BM25 | MiniSearch + jieba | `minisearch` 7.x，`@node-rs/jieba` 2.x |
| 契约校验 | Zod | 3.25 |
| 状态库 | better-sqlite3 | 13.x，WAL |
| 并发/韧性 | p-queue + cockatiel | 队列、超时、熔断 |
| 鉴权 | express-session + jose + ldapts | 文件会话、JWT、LDAP |
| MCP | `@modelcontextprotocol/sdk` | 1.25.3，Streamable HTTP |
| 日志/指标 | pino + pino-roll + Prometheus client | 脱敏、轮转、`/metrics` |
| 文件监听/锁 | chokidar + proper-lockfile | 热更新与发布互斥 |

> 没有引入 LangGraph；编排是显式 `runChat` + LCEL，不是状态图。面试时不要说“用了 LangGraph”。

### 前端 `frontend/`（端口 9966）

Vue 3.5 + TypeScript + Zod + Element Plus + Vite 6。只通过 HTTP API 访问服务端，不包含检索/生成逻辑。

### 评测平台 `review/`（端口 9968）

TypeScript + Express + Vue 3 + Element Plus + Chart.js。通过 HTTP 调服务端，不 import 服务端实现；报告写入 `review/reports/`。

## 服务端分层

```text
server/src

├─ config/       .env 校验、常量、路径、日志配置
├─ documents/    文档加载、Markdown 解析、切块、父块、图片、元数据
├─ indexing/     索引构建、LanceDB、BM25、manifest、发布、热更新、健康度
├─ retrieval/    意图、查询计划、别名、实体、向量/BM25/精确召回、融合、父块、证据补强
├─ generation/   查询改写、会话记忆、Prompt、LCEL、JSON 解析、形态分类、证据、守卫、清洗、流式、代码排错
├─ models/       ChatOpenAI / OpenAIEmbeddings 与网关协议适配
├─ history/      服务端会话历史仓储、轮次/步骤账本
├─ ops/          SQLite、trace、指标、问题队列、重放、备份、异常扫描
└─ schemas/      对外 Zod 契约（search / chat / answer / chatHistory / session）
```

### 应用层（app）

- `server/src/app/server.ts`：进程入口。加载 env → 建 runtime → 启动 docs watch / index poller → 建 app → listen → 注册优雅关闭。
- `server/src/app/app.ts` 的 `createApp()`：挂中间件（helmet、cors、json、traceId、clientIp、session）、静态资源、鉴权、限流、`/api/search`、`/api/chat`、`/api/feedback`、会话历史、健康检查、`/metrics`、MCP、`/ops`。
- `server/src/app/runtime.ts`：运行时对象。索引、embedding、chat model、retriever、SQLite、会话仓储、检索/问答队列、熔断器、在途计数、热加载函数。
- `server/src/app/lifecycle.ts` / `server/src/app/shutdown.ts`：在途计数、AbortSignal 合并、HTTP 服务有界关闭。

### 运行时对象（RagRuntime）

```text
RagRuntime
├─ env / docsDir / dataDir
├─ index?: { version, builtAt, path, embeddingModel }
├─ indexHandle?: { pointer, manifest, store, bm25, parents, catalog }
├─ embeddings?: EmbeddingsInterface
├─ chatModel?: ChatOpenAI
├─ retriever?: ThingJSRetriever
├─ catalog: ClassEntry[]
├─ aliases: AliasTable
├─ db: RagDb
├─ chatHistory: ChatHistoryStore
├─ searchQueue: PQueue(SEARCH_CONCURRENCY)
├─ askQueue: PQueue(CHAT_CONCURRENCY)
├─ askBreaker: circuitBreaker(5 次连续失败, 30s 半开)
├─ inflight: InflightTracker
└─ reloadIndex(options): Promise<RuntimeIndex | null>
```

**热切换的原子性**：`reloadIndex` 先完整加载新版本的 LanceDB、BM25、parents、catalog，全部成功后才一次性替换 `runtime.indexHandle / retriever / index`。加载失败时旧对象继续服务，并把 `active.json` 回滚到上一版。

**索引与 Embedding 一致性**：加载时校验 `active.json` 的模型/维度、manifest 的模型/维度、env 的 `EMBEDDING_MODEL / EMBEDDING_DIMENSIONS` 四者一致；不一致返回 `index_embedding_mismatch`，服务照常启动但检索/问答 503。

## 请求生命周期

### 检索 `POST /api/search`

```text
请求
→ attachTraceId（x-trace-id 或新 traceId，回写响应头）
→ attachClientIp
→ webAuth / bearer 鉴权
→ express-rate-limit
→ Zod 校验 SearchRequest
→ AbortController：客户端断开 / 服务关闭都中止
→ runtime.searchQueue（并发 8，队列上限 256，单次 120s）
→ ThingJSRetriever.retrieve()
   → 意图识别
   → 查询计划
   → 向量 + BM25 并行召回
   → RRF 融合
   → 采纳/丢弃、精确置顶
   → 父块有界补全
   → 格式化 context
→ retrievalToSearchResult
→ insertTurn（审计 + detail）
→ JSON 响应
```

### 问答 `POST /api/chat`

```text
请求
→ 鉴权 / 限流 / Zod
→ preflightWebChat（网关模式下每轮查账号、配额、模型权限）
→ 本地配额（免登录模式）
→ 解析 history（最多 12 条，每条 4000 字符）
→ 选 chatModel：登录用户用其网关 token；兼容模式用服务端 Key
→ 若 stream=true：开 SSE
→ runChat()
   → 判断独立切题 / 追问；独立切题跳过改写和摘要
   → 组装会话记忆：会话要求 + 摘要 + 最近问答组 + 相关历史
      → 按 rewrite / summary / answerShape / answer / code 五阶段预算裁剪
   → 检索（同上；code_debug 走代码/报错意图）
   → 回答形态分类（与检索并行，失败回退 simple）
   → 生成：Prompt → 模型 → JSON 解析 → 证据筛选 → 守卫 → 可能重试 → 清洗 → 引用
   → 输出后置校验：finish_reason=length 或 completionTokens 超阶段上限则降级
   → 汇总 usage / timing / confidence / memory trace / degraded
→ insertTurn（成功或失败都落）
→ JSON 或 SSE done/error
```

### 关键中止语义

- **客户端断开**：`res.on('close')` / SSE `onClose` 触发 abort，检索或生成会收到 signal，记录 `client_aborted`（HTTP 499）。
- **服务关闭**：`shutdownController.abort()` 合并进每个请求的 signal，记录 `server_shutdown`（503）。
- **队列满**：检索返回 429 `queue_full`；生成返回 503 `chat_busy`。
- **队列超时**：检索 504 `retrieval_timeout`；生成 504 `chat_timeout`。
- **生成失败**：只有非中止、非网关致命错误、非队列错误才会降级为「返回检索片段」；鉴权/配额/限流错误不会被伪装成降级答案。

### 会话状态与配置版本

- `chat_turns` 记录一轮状态（`running / ok / error / interrupted / cancelled`），`chat_steps` 记录 summary / rewrite / answer-shape / answer / scene-code / code-debug 的模型调用；用户消息在模型调用前先入账。
- 同一会话同时只允许一个 running turn；重复 `clientTurnId` 幂等；服务启动时把遗留 running 标记 `interrupted`。
- 重试：请求带 `retryOfUserClientId` / `retryOfAssistantClientId`；服务端校验会话归属、角色和配对，非法统一 400 `invalid_retry_reference`；新助手消息保存 `source_user_client_id`。
- 评测平台的配置版本 = sha256(`promptVersion + indexVersion + chatModel + judgeModel + retrievalConfigHash`) 前 16 位；报告、回归确认、发布检查共用同一个口径。

## 并发与韧性

| 机制 | 实现 | 参数 |
| --- | --- | --- |
| 检索并发 | p-queue | 8 并发，队列 256，单任务 120s |
| 问答并发 | p-queue | 4 并发，队列 64，队列超时 `max(120s, CHAT_TIMEOUT_MS×3)` |
| 模型重试 | `RunnableLambda.withRetry` | 最多 2 次（含首次），只对瞬时错误 |
| 熔断 | cockatiel `circuitBreaker` | 连续 5 次失败断开，30s 后半开 |
| 限流 | express-rate-limit | 检索 120/min，问答 30/min，登录 20/min |
| 请求超时 | OpenAI client / 队列 / 网关预检 | chat 60s，embedding 60s，预检 3s/15s |
| 优雅关闭 | Abort + 队列 drain + HTTP close | 最多 15s 强制退出，在途 drain 3s |
| 索引发布互斥 | proper-lockfile | `publish.lock`，stale 10min |

**为什么生成阶段单独排队**：模型调用是最慢、最占网关连接的一段。检索可以先跑，生成必须显式排队，否则高并发会打爆网关。队列满/超时是服务端结论，不能降级吞掉。

## 横切能力

### traceId 与日志

- `attachTraceId` 使用 `AsyncLocalStorage` 传播 traceId。
- traceId 形如 `m3k9x2-a1b2c3d4`（时间戳 base36 + uuid 前 8 位）。
- pino 日志统一脱敏：`authorization`、`token`、`apiKey`、`OPENAI_API_KEY`、`EMBEDDING_API_KEY`、`AUTH_JWT_SECRET`、`LDAP_BIND_PASSWORD`。
- prompt 正文不写日志；调用详情写 SQLite 的 `detail`，供观测台查看。
- 设置 `LOG_FILE` 后 `pino-roll` 按大小轮转，默认 10m、保留 5 份；同时保留 stdout。

### 错误映射

- `HttpStatusError`：业务已知错误，保留原文案和状态码。
- 网关错误：`mapGatewayError` 把 401/403/429/504 映射成 `invalid_token / user_disabled / model_forbidden / quota_exceeded / rate_limited / queue_timeout`。
- 未知错误：对外统一「服务暂时不可用」，细节只进日志。
- 请求体 JSON 解析失败：400 `bad_request`。

### 安全基线

- helmet 开启（CSP 先关闭，因为静态页有内联脚本；跨源资源策略放开文档图片）。
- CORS 白名单由 `CORS_ORIGINS` 控制；允许 MCP 会话头、traceId、评测运行头。
- `trust proxy` 默认 1；直连部署必须设 `TRUST_PROXY=0`，防止伪造 `X-Forwarded-For` 绕过限流。
- 请求体上限 2 MB；会话消息单条 response 上限 1 MB。
- 运维只读接口默认 `OPS_READ_LOCAL_ONLY=true`，只允许回环地址；写操作（问题创建/更新、重放、热加载、prune）只允许回环。
- `.env` 只在 `server/.env`，不提交、不打印、不写日志/报告/fixture。

## 三个入口

1. **Web 问答页**：会话列表、流式回答、引用卡片、检索/提示词/耗时检查器、点踩反馈、网关配额。
2. **MCP**：`search_thingjs_docs`、`ask_thingjs_docs` 两个工具，供 IDE/Agent 调用。
3. **评测平台**：调用观测台、趋势、问题队列、评测历史、回归验证、发布检查六视图。

## 面试时的项目一句话

> 「这是一个以 LangChain JS 0.3 重建的 ThingJS 文档 RAG 服务。它把文档和 demo 代码切成 9,366 个语义块，做向量 + BM25 混合检索，用查询计划、精确符号召回和 SQLite 符号证据解决口语化/错拼/否定约束；生成侧用结构化 JSON、回答形态分类、证据守卫和确定性清洗控制幻觉，并用会话记忆按需组装上下文；同时用 100 题检索集、30 题生成集、三套门禁、配置版本和问题闭环把质量变成可回归的工程指标。」

## 源码入口

- 优雅关闭：`server/src/app/shutdown.ts`
- 鉴权中间件：`server/src/app/auth/middleware.ts`
- Web 会话：`server/src/app/auth/webSession.ts`
- MCP 挂载：`server/src/app/mcp/mount.ts`
- 运维路由：`server/src/ops/server.ts`
- 检索器：`server/src/retrieval/thingjsRetriever.ts`
- 生成器：`server/src/generation/generate.ts`
- 迁移记录：`MIGRATION.md`
