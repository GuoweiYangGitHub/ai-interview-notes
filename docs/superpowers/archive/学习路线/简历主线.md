# 简历主线

> 这条线不是“从零转 AI”，而是“前端基础 → 数字孪生 → AI 应用”。面试时先让面试官相信工程能力，再证明 AI 应用深度。

## 一句话版本

近 10 年前端开发，2022 年起做数字孪生，2025 年起做 AI 应用；主栈 TypeScript / Node.js，前端以 Vue 3 为主。最近两个项目：江中智能助手（Agent 编排 + 对话前端）和 ThingJS 文档 RAG（检索 + 生成 + 评测）。也做过集团级网络拓扑和千万级会员小程序。

## 两个 AI 项目的简历级 bullet

### 江中智能助手（2026.03–2026.07）

- 独立交付 Vue 3 对话前端和 TypeScript / Express 服务端；前端做流式对话、审批卡、会话恢复和场景回执。
- 服务端用 LangGraph 按 `classify → route → act` 组织多步任务；只读计划支持依赖调度和并行，写操作必须人工确认。
- 工具从 MCP 目录动态绑定，参数用 JSON Schema / Ajv 校验；三维动作交给宿主执行，没有回执不算成功。
- 会话、图状态、任务卡、审批和场景回执存 PostgreSQL；服务重启后能续接，关掉页面任务可继续跑。
- 评测分 L1 固定断言和 L2 完成率 / 安全拦截 / 数值溯源；审阅台支持回放、人工标注和回归用例。

对应页面：[项目全景与架构](/03-项目实战/02-江中智能助手/01-项目全景与架构) · [面试问答](/03-项目实战/02-江中智能助手/11-面试问答) · [数字速查与讲法](/03-项目实战/02-江中智能助手/10-数字速查与讲法)

### ThingJS 文档 RAG（2025.07–2025.10）

- 负责前端、检索、生成和评测；网页助手和编辑器 MCP 共用一套检索、生成链路。
- 文档按 Markdown 结构和代码 AST 切分，保留父块；检索走精确符号、向量、BM25，用 RRF 融合，再做类 / 成员采纳和父块回填。
- 生成用 YAML Prompt + LCEL，做证据筛选、领域守卫和引用校验。
- 索引按文件 hash 增量构建，manifest 校验后切 active 指针；docs 改动可热更新，发布门禁失败回滚。
- 评测覆盖检索、生成和回归门禁；检索看类 / 成员命中与误空，生成看正确性、引用依据和幻觉。

对应页面：[项目全景与架构](/03-项目实战/01-THINGJS文档RAG/01-项目全景与架构) · [项目问答](/03-项目实战/01-THINGJS文档RAG/12-项目问答) · [面试讲法](/03-项目实战/01-THINGJS文档RAG/10-面试讲法)

## 面试讲述顺序

### 30 秒

> 我近 10 年做前端，2022 年起做数字孪生，2025 年起把主要精力转到 AI 应用。主栈是 TypeScript / Node.js，前端以 Vue 3 为主。最近独立交付了江中智能助手的对话前端和服务端，也做了 ThingJS 文档 RAG 的检索、生成和评测。我的优势是把 AI 能力真正接进业务，并且能评测、能发布、能兜底。

### 3 分钟

1. **前端底子**：十年 Web 前端，做过金融后台、千万级用户小程序、数字孪生大屏。
2. **数字孪生**：中国移动网络拓扑的 3D/2D 布局与聚合下钻；江中助手的场景定位与宿主回执。
3. **江中助手**：`classify → route → act`、LangGraph 子图、MCP 工具、写操作审批、场景回执、PostgreSQL 状态。
4. **ThingJS RAG**：结构化切片、混合检索、RRF、父块、证据守卫、索引发布和评测门禁。
5. **收尾**：我不是只做 Demo，而是把 AI 应用当成可运维的工程系统来做。

## 需要补强的边界

- **模型训练 / 微调**：没有生产级微调经验；被问到时讲清什么时候该微调、什么时候用 RAG / Prompt，别硬编。
- **大规模分布式**：两个项目以单实例或有限并发为主；多实例扩展能讲方案，但要说明还没在生产验证。
- **Python / FastAPI**：主栈是 TypeScript / Node；Python 能读能改，但不冒充主力语言。
- **算法深度**：前端算法够用，不往算法工程师方向包装。
