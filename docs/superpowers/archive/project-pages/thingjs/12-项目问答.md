# THINGJS 文档 RAG · 项目问答
> 一句话定位：R01–R18 高频追问的逐题答法；与 09/10/11 重复的题只保留定位句和链接，不重复长答案。

## 使用说明

- 每题按 `答题要点` 组织；源文有额外追问或反常识补充时给 `加分句`。
- 数字口径以 [10-面试讲法](/03-项目实战/01-THINGJS文档RAG/10-面试讲法) 为准；索引与检索细节见本题要点。
- 不要把“最近一次”和“历史通过版本”混写：生成最近一次是 23/24 被拦截，历史通过是 24/24、裁判 95.8%。

## R01–R06

### [重点] R01 · 用一分钟讲清这个 RAG 项目。你的工作做到了哪一层？

**答题要点**

- 面向 ThingJS API 文档；网页助手和编辑器 MCP 共用索引与检索链路。
- 我负责文档切片、混合检索、证据选择、引用检查、索引发布，以及检索与回答质量评测和请求回放。
- 例子：「摄像机看向某点」这类口语，要先找到 `Camera` 和 `lookAt`，再根据原文给出用法与引用。
- 完整 60 秒版本见 [10-面试讲法](/03-项目实战/01-THINGJS文档RAG/10-面试讲法)；项目事实见本题要点。

**加分句**

> 我不是只做了“检索 + 调模型”，而是把索引发布、证据链、评测门禁和问题闭环都做成了可回归的工程系统。

### R02 · API 文档为什么按类和成员切片？改一个切块参数会怎样？

**答题要点**

- API 的签名、说明和示例通常围绕同一个成员组织；先按成员切，可以让这组信息留在同一片段里。
- 超过 800 字的同一成员再分段，相邻段目标重叠 200 字，尽量保持代码块完整。
- 切块参数进入指纹；参数变化后需要重新生成向量索引，因为片段内容和边界都可能变了。
- 当前活动索引已切到 target 900 / max 1200 / overlap 150；`800/200` 是旧 H3 基线。详见本题要点。

### [重点] R03 · 向量和 BM25 各解决什么？为什么用 RRF？

**答题要点**

- BM25 适合匹配明确的 API 标识符；向量补足中文口语和语义接近的表达。
- 两路原始分数的含义不同，RRF 用各自的排名计算贡献，再把同一片段的贡献相加；两路都排得靠前的片段会得到更高分。
- 这个融合按排名工作，原始分数差距不参与计算；实现用 LangChain 官方 `EnsembleRetriever`，没有手写 RRF 数学。
- 详细链路见本题要点，逐题话术见 [11-八股项目答法](/03-项目实战/01-THINGJS文档RAG/11-八股项目答法)。

**加分句**

> RRF 之后还要做片段选择：融合决定候选顺序，多类配额决定哪些候选最终进入模型上下文。

### R04 · 用户写错了类名，为什么选择规则纠错？会不会改错？

**答题要点**

- 使用别名表和类目录做扩展与近邻纠错，可以把规则的候选范围限定在已有 API，也省去一次模型调用。
- 纠错只在编辑距离 ≤2 且唯一命中时生效；并列时不猜，短词只接受显式 ThingJS 上下文中的相邻换位。
- 评测把口语、拼写错误和点名成员分开看，避免总体分数掩盖某类退步。
- 排查误改时，比较原始问句、纠错结果、两路候选和最后采用的证据，判断是扩展带偏还是排序出了问题。

**加分句**

> 规则纠错最大的优势是可解释：每一步都能在 trace 里看到原词、候选、命中的别名或类名。

### [重点] R05 · 同时问 Box、Sphere 和 Cylinder，为什么明明召回了三个类，答案还是漏一个？

**答题要点**

- 目标类可能在融合列表里，但没有进入生成上下文；直接取前几条时，高排名的某一个类可能占满名额。
- 项目对多类问题按类分配片段、轮流选取，同一类里优先保留点名成员；D 源口径是每类最多 3 条，当前实现以响应 `effectiveTopK` 为准。
- 排查时先看每一路召回，再对比融合列表和实际采用列表，确认漏在哪一步。
- 完整检索机制见本题要点，多类话术见 [11-八股项目答法](/03-项目实战/01-THINGJS文档RAG/11-八股项目答法)。

**加分句**

> 这是“先复现失败用例 → 改 → 用门禁验证”的典型：T07 五类创建问句暴露后，才给每个类补一路「类名 + 构造函数 概述」BM25。

### [重点] R06 · 有引用就说明答案可信了吗？引用检查能保证什么？

**答题要点**

- 运行时先确认引用指向本轮真正送进模型的证据，已丢弃的片段不能被引用；这一步验证出处是否有效。
- 句子里的事实是否由该证据支持，还要对照内容检查；引用合法 ≠ 答案正确。
- 固定题集通过规则和 LLM 裁判分别检查引用、回答依据和相关性。
- 完整引用机制见本题要点，引用话术见 [11-八股项目答法](/03-项目实战/01-THINGJS文档RAG/11-八股项目答法)。

## R07–R12

### R07 · 什么时候拒答？模型服务挂了又该怎样？

**答题要点**

- 目录外类名等情况可以直接返回空结果；筛选后没有可用证据时，说明资料不足并跳过生成。
- 已有有效证据但生成服务故障时，可以降级返回检索片段。
- 两种情况需要分别记录，便于区分资料缺失和生成服务不可用。
- 关键边界：鉴权/配额/队列错误不伪装成降级，见本题「降级」要点。

### [重点] R08 · 你说的两套黄金集是哪两套？“生成”指自动出题吗？

**答题要点**

- 按评测环节分：检索黄金集 100 题，标注预期 API 类、成员或负例，用来检查目标证据有没有找到；检索题在脚本里维护，再输出为 JSON。
- 回答生成黄金集 30 题，其中 24 道预期回答、6 道预期空结果，题目由手写维护，包含引用、必提术语、代码块或参考事实等预期。
- “生成”指模型产出的回答，不是自动出题；口语、拼写错误、成员等是各题集内部的题型标签。
- 完整夹具见本题要点。

**加分句**

> “摄像头如何看向某个物体”这类检索题要找到 `Camera.lookAt`；回答评测还要进一步核对用法有没有答对、引用能否支持回答。

### [重点] R09 · 检索怎么打分？总命中率很高就能发版吗？

**答题要点**

- 类命中看预期类是否进入计分窗口；成员命中在要求成员的题里，看预期类和成员是否同时进入前 3 条。
- 误空用于发现文档有答案却返回空的情况；还会按口语、成员和拼写等分层看指标，防止总体分数掩盖某类退步。
- 报告里有不同的 Hit@K 指标；解释发版门槛时，按实际计分窗口和题目分母说明。
- 高命中率不等于能发版：还要看基线对比、生成门禁、回归、P0/P1 和发布阈值。详见本题要点。

### R10 · 为什么用 LLM 裁判？怎样降低评分波动？

**答题要点**

- 结构、引用是否有效、是否包含必提内容，可以先做规则检查。
- 回答是否切题、事实是否来自证据、引用是否支持对应说法，再交给裁判模型。
- 用固定题集、参考事实、统一评分规则和低温度保持可比性；当前裁判温度 0，12 条人工样本校准。
- 遇到关键题分数变化，回看问题、证据、回答和判分理由，必要时人工核对。

### [重点] R11 · 一篇文档改了，怎么增量建索引并安全发布？

**答题要点**

- 通过文件指纹识别变更，未变文件复用已有向量。
- 候选索引单独构建，构建期间服务继续使用旧版。
- `publish:index` 在构建后校验并激活候选索引，再通知服务热加载。
- 启用的检索与生成门禁随后通过服务运行；未通过时，脚本在有可用旧版本的情况下重新激活旧版并尝试热加载。
- 面试时把索引结构校验、切换和质量门禁这三个步骤分开讲；更换 Embedding 模型或切块规则时，按新配置重建。
- 完整发布流程见本题要点。

### R12 · 网页和编辑器共用知识库，MCP 的 API Key 能隔离客户文档吗？

**答题要点**

- API Key 控制调用资格并按 Key 记录用量；网页和编辑器共用检索链路，网页有独立的日 token 池。
- 当前语料的来源标记用于追溯，文档级 ACL 尚未实现。
- 如果需要按客户或产品线隔离，服务端要在检索阶段强制限定可见范围，而不是只靠 Key 区分。

**加分句**

> 不要把“有 API Key”说成“有文档级权限”；当前是调用资格和用量隔离，不是语料级隔离。

## R13–R18

### R13 · 线上空答突然增加，怎么排查？评测流量算进去吗？

**答题要点**

- 先在运维页按网页、MCP 和评测流量分开看；评测调用带 `source=eval` 标记，不应混进生产空答率。
- 挑一条空答回放，检查问句分类、查询改写、候选片段、最终采用和置信状态。
- 再对照索引版本、Embedding 或生成服务的健康情况。
- 先确认空答是预期拒答、召回问题还是下游故障，再决定调整规则、索引还是服务。
- 排查路径见本题要点，话术见 [11-八股项目答法](/03-项目实战/01-THINGJS文档RAG/11-八股项目答法)。

### [重点] R14 · 给你一份评测报告，怎么解释检索分母、负例和裁判分歧？

**答题要点**

- 先确认是全量还是子集，使用哪个题集和评分版本。
- 严格类命中按本题实际采用窗口检查预期类，多类题要看全部预期类。
- 严格成员命中只评有成员要求的题，核对同一片段上的类名和成员名是否同时匹配。
- 缺必要元数据的题单列为无法评分；负例检查是否正确拒答；HTTP 错误或坏 JSON 作为执行错误记录。
- 若人工和裁判意见不一致，先回看题目、参考事实、实际证据、答案和评分理由，再判断是裁判规则需要校准，还是系统本身有问题。

**加分句**

> 字段叫 `classHitAt8`，不能直接当严格 Top 8 指标；报告保留了旧字段，讲严格评分时要看 `effectiveTopK`、严格指标和对应分母。

### R15 · Embedding 压测写了 1024 并发，连接池为什么只有 32 条连接？整个问答也能跑到这个量吗？

**答题要点**

- 1024 指客户端同时发起的请求数，连接池最多使用 32 条长连接，其余请求在客户端排队。
- 留档中这个档位两组测试都得到 2048/2048 成功，测量范围是短中文问句调用 `Qwen3-Embedding-4B` 返回向量。
- 要评估完整问答容量，需要分别测 Embedding、双路检索和生成，再做端到端压测。
- 报告时同时给成功数、等待时限和延迟。

**加分句**

> 不要把 Embedding 的并发数字直接说成“问答 QPS”；两者测的不是同一个东西。

### [重点] R16 · 磁盘上已激活新版，但热加载报错。现在到底哪一版在服务？怎么处理？

**答题要点**

- 先分别查磁盘上的 active 指针和进程当前加载的版本；指针可能已经指向新版，进程仍持有旧版。
- 用服务返回的 `indexVersion` 或运维信息确认实际版本，再结合热加载日志决定重试加载，或重新激活已知可用的旧版后再加载。
- 恢复后用实际检索响应核对；发布脚本用文件锁串行化发布。
- 若还需要保证候选索引覆盖了构建期间的新变更，要另外核对文档版本并安排重建。

**加分句**

> 门禁失败和热加载失败不是一回事：当前脚本在热加载失败时退出；质量门禁失败有单独的回滚路径，会在可用时恢复旧指针并尝试重载。

### R17 · 换了 Embedding 模型但维度没变，旧向量能复用吗？服务启动时怎么检查？

**答题要点**

- 相同维度只能说明向量长度一样；换模型后，查询向量和旧文档向量的语义空间可能不一致，应该按新模型重建文档向量。
- 项目按 Embedding 模型管理索引 profile，校验时对照 manifest 与环境配置里的模型、维度和 query instruction 配置，再抽查索引里的向量与检索数据。
- 实际排查还要确认上游模型别名指向哪个模型。

**加分句**

> “维度一致”是必要检查，不是复用依据；真正的复用条件是模型、维度、切块指纹都一致。

### R18 · 单机磁盘坏了，哪些数据需要恢复，哪些可以重建？怎么验收？

**答题要点**

- 先分两类：请求和回放记录在 `rag.sqlite`，需要恢复已有备份；项目备份还保存别名和激活指针。
- 索引可在有原始文档、切片配置和 Embedding 模型的情况下重建，也可以从另有留存的索引制品恢复；激活指针指向的版本必须实际存在。
- 验收先验证 SQLite 备份，再检查当前索引版本、模型配置和可用性，实际跑一条检索和一条历史回放。
- 备份/恢复命令与校验见本题要点。
