# CSS 兼容与跨端

> 汇总移动端兼容问题、浏览器差异和跨端方案，重点是 1px、输入法与 JSBridge。

## 浏览器兼容

### font-weight: 500 在 Android 无效

`font-weight: 500` 之所以无效，是系统使用的字体不支持，例如 Windows 的微软雅黑、宋体；iOS 的字体支持该字重。所以同一个样式在 iOS 有效、Android 无效。需要精确字重时，应使用支持对应字重的字体文件。

### backdrop-filter 的兼容性

`backdrop-filter` 大部分浏览器都兼容（不考虑 IE），可用于毛玻璃效果。

```css
.box {
  backdrop-filter: blur(10px);
}
```

完整滤镜列表见[知识点：backdrop-filter 背景滤镜](./知识点.md#backdrop-filter-背景滤镜)。

## 移动端

### 移动端 1px 问题

`devicePixelRatio = 物理像素 / CSS 像素`，在高清屏上 1px 的 CSS 边框会被渲染成多个物理像素，看起来偏粗。

使用伪元素 + `transform: scale`：

```scss
.div::after {
  content: '';
  box-sizing: border-box;
  position: absolute;
  z-index: 1;
  left: 0;
  top: 0;
  width: 300%;
  height: 300%;
  border: 1.5px solid #bfbfbf;

  transform: scale(1/3);
  transform-origin: left top; /* 缩放原点 */
  border-radius: 6px;
}
```

### Android 端文字未垂直居中

1. 通过 `line-height` 等于 `height` 设置时有时会出现未垂直居中，换用 Flex 布局的 `align-items: center`。
2. 小于 12px 大小的字体会偏上，可通过 `transform: scale()` 和 `transform-origin` 控制字体缩放。

### iOS 页面底部 margin-bottom 失效

设置一个空的 `div` 撑起 `margin-bottom` 设置的高度。

### absolute 定位元素被输入法顶起

当 absolute 元素的父元素设置 `height` 等于屏幕高度时，输入法弹起、屏幕高度缩小，会导致定位元素被顶起，遮盖其他元素。

解决方法：input 获取焦点时，让定位元素隐藏或改成静态定位；失去焦点时恢复。

### 输入法弹窗导致窗口变小

输入法弹窗显示时，会导致 `window` 窗口高度变小。

场景：页面 A 在输入法弹窗显示时跳到页面 B，会导致页面 B 通过 `window.innerHeight` 获取的高度有问题。

解决方法：

1. 跳转页面之前，先用 `document.activeElement.blur()` 隐藏虚拟键盘，然后延时 300 毫秒再跳转。
2. 跳转前先通过 `window.innerHeight` 获取输入法未弹起时的内容窗口高度，再通过地址拼接传递该高度。

### 手机端表单元素的默认外观重置

```scss
.input {
  -webkit-appearance: none;
}
```

### 小程序图片闪动变形


- 如果设置了 `widthFix`，则手动将 `height` 调整为 `auto`。
- 如果设置了 `heightFix`，则手动将 `width` 调整为 `auto`。

```html
<style lang="scss">
  .widthFix {
    height: auto;
  }

  .heightFix {
    width: auto;
  }
</style>

<image
  class="widthFix"
  mode="widthFix"
  src="https://example.com/demo.jpg"
/>

<image
  class="heightFix"
  mode="heightFix"
  src="https://example.com/demo.jpg"
/>
```

### 手机端使用 ECharts 的常见问题

- 同一个 ECharts DOM 要渲染两种不同类型的图表时，先调用 `echartsDOM.clear()` 移除实例中所有组件和图表。
- 移动端 ECharts 字号设置不受浏览器最小字号限制，可以随意设置更符合界面显示需要的字号。
- tooltip 默认出现在用户交互的数据点附近，手机端可能显示不全，可以动态设置 tooltip 的位置。

## 跨端方案

### 跨终端解决方案

- Flutter
- Taro
- React Native
- H5 Hybrid
- 桌面端对应方案是 Electron

### 跨终端 Web 适配方式

- 写多套代码，输入网址时判断 PC 或 mobile，返回对应内容。
- 响应式设计，例如 Bootstrap。

### 跨终端通信：JSBridge

Web 端和 Native 可以类比为 Client/Server 模式：Web 端调用原生接口就像 Client 向 Server 发送请求，JSBridge 充当类似 HTTP 协议的角色。

实现 JSBridge 主要做两件事：

- 将 Native 端的原生接口封装为 JavaScript 接口。
- 将 JavaScript 接口封装为原生接口。

常见开源实现：

- DSBridge：主要通过注入 API 的形式，有 `DSBridge for Android`、`DSBridge for IOS`。
- JSBridge：主要通过拦截 URL Schema 的形式。
