# 小程序面试题
> 登录流程、启动过程、双线程原理、生命周期、优化与 webview 通信。

## 登录与启动

### [重点] 小程序登录流程


1. 调用 `wx.login()` 获取临时登录凭证 code，有效期为 5 分钟。临时登录凭证 code 只能使用一次。
2. 将临时 code 传到后端，后端调用 `auth.code2Session` 接口，换取用户唯一标识 `OpenID` 和会话密钥 `session_key`。openid 是用户唯一标识；session_key 能保证当前用户进行会话操作的有效性。
3. 获取 `session_key` 出于安全性考虑，要在后端调用。如果在前端通过 request 调用此接口，不可避免要将小程序的 appid、secret 和服务端下发的 `session_key` 暴露在外部，会给业务安全带来极大风险。`session_key` 拥有一定的时效性，用户越久未使用小程序，登录态越可能失效；反之如果用户一直在使用，登录态一直保持有效。具体时效逻辑由微信维护，对开发者透明。开发者需要调用 `wx.checkSession` 接口检测当前用户登录态是否有效。
4. 后端自定义新的密钥并关联返回的 `session_key` 和 `openid`，将新密钥返给前端，前端将其存储在 storage 中。会话密钥 `session_key` 是对用户数据进行加密签名的密钥，为了应用自身的数据安全，开发者服务器不应该把会话密钥下发到小程序，也不应该对外提供这个密钥，所以要定义新的密钥。之所以存在 storage 中，是因为小程序没有 cookie，相应的后端 set-cookie 在小程序中不起作用。
5. 前端发送请求时带着密钥，后端根据密钥识别用户身份，返回数据。

### [重点] 打开一个小程序到页面展示，经历了什么

1. 启动小程序。
2. 运行环境准备。
3. 下载代码包。
4. 缓存代码包。
5. 代码注入。
6. 逻辑层与渲染层双线程并行。
7. 渲染页面。

## 数据与生命周期

### 小程序的 v-model 和 Vue 的有什么不一样

小程序设置 `this.data` 不会被同步到视图，必须调用：

```js
this.setData({});
```

### [重点] 生命周期

#### App 生命周期

- `onLaunch`
- `onShow`

#### 执行顺序

```js
// 生命周期执行顺序
onLaunch(app.js) -> onShow(app.js) -> attached(组件) -> onLoad(页面) -> onShow(页面)
```

#### Page 页面生命周期

```js
Page({
  onLoad: function (options) {
    // 生命周期回调—监听页面加载，只加载一次
  },
  onReady: function () {
    // 相当于 Vue mounted
    // 生命周期回调—监听页面初次渲染完成
  },
  onShow: function () {
    // 每次切换都会显示
    // 监听小程序显示。小程序启动，或从后台进入前台显示时
  },
  onHide: function () {
    // 每次切换都会隐藏
    // 监听小程序隐藏。小程序从前台进入后台时
  },
  onUnload: function () {
    // 页面销毁
  },

  // --------------- 以下不是生命周期钩子函数 ----------------
  onPullDownRefresh: function () {
    // 监听用户下拉动作
  },
  onReachBottom: function () {
    // 页面上拉触底事件的处理函数
  },
  onShareAppMessage: function () {
    // 用户点击右上角转发
  },
  onPageScroll: function () {
    // 页面滚动触发事件的处理函数
  },
  onResize: function () {
    // 页面尺寸改变时触发
  },
});
```

#### 组件生命周期

```js
Component({
  lifetimes: {
    created: function () {
      // 在组件实例刚刚被创建时执行
    },
    attached: function () {
      // 在组件实例进入页面节点树时执行
    },
    ready: function () {
      // 在组件在视图层布局完成后执行
    },
    moved: function () {
      // 在组件实例被移动到节点树另一个位置时执行
    },
    detached: function () {
      // 在组件实例被从页面节点树移除时执行
    },
    error: function () {
      // 每当组件方法抛出错误时执行
    },
  },
});
```

### [重点] 小程序的优化

- 控制图片大小以及比例。
- 避免 wxml 节点数过大。
- 滚动区域设置惯性滚动：`-webkit-overflow-scrolling: touch`。
- 避免短时间内发起太多请求（使用懒加载）。
- 合理使用分包。
- 减少 data 的大小，非必要不 `setData`。
- 组件化。
- 按需注入。

## 事件与 webview

### bindtap 与 catchtap 的区别

`bindtap` 不会阻止事件冒泡，`catchtap` 会阻止事件冒泡。

### webview 中的页面怎么跳回小程序中？

```js
wx.miniProgram.navigateTo({ url: '/pages/index/index' });
```

### webview 的页面怎么跳转到小程序导航的页面？

通过 `switchTab` 跳转，但默认情况下不会重新加载数据。若需要重新加载数据，则需要在 `success` 属性中手动调用。

```js
// 在 webview 中的 success 属性中添加以下代码
success: function (e) {
  var page = getCurrentPages().pop();
  if (page === undefined || page === null) return;

  page.onLoad();
}
```

### webview 怎么跟小程序通信？

- webview 向小程序发送数据，通过 `wx.miniprogram.postMessage()` 通信。
- 小程序通过 `bind:message` 接收，但只有在页面后退、分享、销毁时才会调用。

### 微信小程序和 h5 的区别

- 运行环境不同
  - 小程序运行在 webview 内核中。
  - h5 运行环境是浏览器。
- 开发成本不同
  - 只在微信中运行，不用顾虑浏览器兼容问题。

## 工程与兼容

### 小程序设置 less

使用 `easy less` 插件，配置一下 `settings.json` 就可以了。

### 小程序怎么阻止页面默认返回

- `wx.enableAlertBeforeUnload(Object object)` 开启小程序页面询问对话框。
  - 弹窗条件：
    - 用户在小程序内非首页页面 / 最底层页。
    - 官方导航栏上的返回。
    - 全屏模式下自绘返回键。
    - Android 系统 back 键时。
  - 注意事项：
    - 手势滑动返回时不做拦截。
    - 在任何场景下，此功能都不应拦住用户退出小程序的行为。
- 使用 `wx.hideHomeButton` 消除页面左上角的返回按钮。

```js
Page({
  onShow: function () {
    wx.hideHomeButton();
  },
});
```

### 小程序绘制海报会出现的问题

- 图片显示不全，或者图片模糊。
- 原因：设置的图片宽高例如为 750 × 1200，但实际在 canvas 画布上画出的尺寸为 375 × 600，图片会显示不全。

#### `wx.canvasToTempFilePath()` 将画布指定区域导出生成指定大小的图片

解决：

- 图片居中问题。
- 生成图模糊问题。

```js
wx.canvasToTempFilePath({
  x: 0,
  y: 0,
  width: 50,
  height: 50,
  destWidth: 100,
  destHeight: 100,
  canvasId: 'myCanvas',
  success(res) {
    console.log(res.tempFilePath);
  },
});
```
