# TypeScript 面试题

> 以 type/interface、泛型、条件类型、类型收窄、工具类型为主线的高频题，答案要点可直接背。

## 类型系统基础

### [重点] type 和 interface 的区别

1. `type` 后面有 `=`，`interface` 没有。
2. `type` 可以描述任何类型组合，`interface` 只能描述对象结构。
3. `interface` 可以继承（`extends`）`interface` 或对象结构的 `type`；`type` 通过 `&` 做对象结构的继承。
4. 多次声明的同名 `interface` 会进行声明合并，`type` 不允许多次声明。
5. `type` 可以使用 `in` 关键字生成映射类型，`interface` 不行。

```ts
type Keys = 'name' | 'sex'
type DuKey = {
  [Key in Keys]: string // 类似 for ... in
}

let stu: DuKey = {
  name: 'wang',
  sex: 'man'
}
```

`type` 通过交叉实现继承：

```ts
type Name = {
  name: string
}

type Person = Name & {
  age: number
}

const people: Person = {
  name: 'ren',
  age: 20
}
```

`interface` 通过 `extends` 继承，`type` 不能通过 `extends` 继承。

补充：`interface` 可以 `extends` 一个 `type`，`type` 也可以与 `interface` 交叉。二者大部分时候可以互换，需要声明合并或扩展第三方接口时选 `interface`，需要联合、元组、映射类型等组合能力时选 `type`。

### 类型别名和接口在扩展上的差异

- `interface` 通过继承扩展，适合逐步添加成员，也支持同名声明合并。
- `type` 创建后不能通过同名声明新增属性，只能重新定义一个交叉类型。
- `interface` 的名字会始终出现在错误信息中；类型别名在 TypeScript 4.2 以前可能被等价的匿名类型替代。

### [重点] 泛型是什么？怎么用

泛型用于描述两个值之间的对应关系，让组件的输入类型和输出类型关联起来，同时保持类型安全。

```ts
function firstElement<Type>(arr: Type[]): Type | undefined {
  return arr[0]
}

const s = firstElement(['a', 'b', 'c']) // string
const n = firstElement([1, 2, 3]) // number
const u = firstElement([]) // undefined
```

多个类型参数：

```ts
function map<Input, Output>(
  arr: Input[],
  func: (arg: Input) => Output
): Output[] {
  return arr.map(func)
}

const parsed = map(['1', '2', '3'], (n) => parseInt(n)) // number[]
```

泛型约束用 `extends`：

```ts
function longest<Type extends { length: number }>(a: Type, b: Type) {
  return a.length >= b.length ? a : b
}

longest([1, 2], [1, 2, 3]) // number[]
longest('alice', 'bob') // 'alice' | 'bob'
// longest(10, 100) // 报错：number 没有 length
```

用另一个类型参数约束：

```ts
function getProperty<Type, Key extends keyof Type>(obj: Type, key: Key) {
  return obj[key]
}

let x = { a: 1, b: 2, c: 3, d: 4 }
getProperty(x, 'a') // ok
// getProperty(x, 'm') // 报错
```

### [重点] 条件类型与 infer

条件类型根据输入类型决定输出类型：

```ts
interface IdLabel {
  id: number
}
interface NameLabel {
  name: string
}

type NameOrId<T extends number | string> = T extends number
  ? IdLabel
  : NameLabel

function createLabel<T extends number | string>(idOrName: T): NameOrId<T> {
  throw 'unimplemented'
}

let a = createLabel('typescript') // NameLabel
let b = createLabel(2.8) // IdLabel
```

用 `infer` 在条件类型中推断类型：

```ts
type Flatten<Type> = Type extends Array<infer Item> ? Item : Type

type Str = Flatten<string[]> // string
type Num = Flatten<number> // number
```

推断函数返回值：

```ts
type GetReturnType<Type> = Type extends (...args: never[]) => infer Return
  ? Return
  : never

type Num = GetReturnType<() => number> // number
type Bools = GetReturnType<(a: boolean, b: boolean) => boolean[]> // boolean[]
```

分发条件类型：传入联合类型时，条件类型会应用到每个成员。

```ts
type ToArray<Type> = Type extends any ? Type[] : never
type StrArrOrNumArr = ToArray<string | number> // string[] | number[]

// 用方括号阻止分发
type ToArrayNonDist<Type> = [Type] extends [any] ? Type[] : never
type NonDist = ToArrayNonDist<string | number> // (string | number)[]
```

### keyof 和 typeof 的区别

- `keyof` 作用于**类型**，返回对象属性名组成的联合类型。
- `typeof` 作用于**值**，在类型位置获取这个值的类型。

```ts
type Point = { x: number; y: number }
type P = keyof Point // 'x' | 'y'

const person = { name: 'kevin', age: '18' }
type Kevin = typeof person // { name: string; age: string }
```

`keyof` 遇到索引签名时直接返回索引类型：

```ts
type Arrayish = { [n: number]: unknown }
type A = keyof Arrayish // number

type Mapish = { [k: string]: boolean }
type M = keyof Mapish // string | number
```

`typeof` 只能用于标识符或属性，不能直接作用于函数调用表达式：

```ts
function f() {
  return { x: 10, y: 3 }
}

type P = ReturnType<typeof f> // { x: number; y: number }
// typeof f() 不合法
```

### 索引访问类型怎么用

```ts
type Person = { age: number; name: string; alive: boolean }

type Age = Person['age'] // number
type I1 = Person['age' | 'name'] // string | number
type I2 = Person[keyof Person] // string | number | boolean
```

结合 `typeof` 与 `as const` 从数组推导字面量联合：

```ts
const APP = ['TaoBao', 'Tmall', 'Alipay'] as const
type app = typeof APP[number] // 'TaoBao' | 'Tmall' | 'Alipay'
```

### 类型断言 as 和非空断言 ! 有什么区别

- `as T`：把值断言为更具体或更不具体的类型，编译时移除，不改变运行时行为。跨度过大的断言会报错，必要时先转 `unknown` 或 `any`。
- `x!`：非空断言，从类型中移除 `null` 和 `undefined`，同样不改变运行时行为。只有明确知道值不为空时才使用。

```ts
const myCanvas = document.getElementById('main_canvas') as HTMLCanvasElement

function liveDangerously(x?: number | null) {
  console.log(x!.toFixed())
}
```

## 类型收窄

### [重点] 类型收窄有哪些方式

TypeScript 会沿着执行路径分析值在某个位置最具体的类型，这个过程叫收窄（narrowing）。

- `typeof` 判断：`typeof padding === 'number'`。
- 真值检查：`if (value)` 排除 `null`、`undefined`、`0`、`''` 等假值。
- 等值判断：`===` / `!==` 收窄字面量类型。
- `in` 操作符：判断属性是否存在于对象。
- `instanceof`：按构造函数收窄。
- 自定义类型判断式（type predicate）：`pet is Fish`。
- `never` 穷尽检查：在 `switch` 的 `default` 分支把值赋给 `never`，新增联合成员时编译报错。

```ts
function isFish(pet: Fish | Bird): pet is Fish {
  return (pet as Fish).swim !== undefined
}

let pet = getSmallPet()

if (isFish(pet)) {
  pet.swim() // Fish
} else {
  pet.fly() // Bird
}
```

穷尽检查：

```ts
type Shape = Circle | Square

function getArea(shape: Shape) {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2
    case 'square':
      return shape.sideLength ** 2
    default:
      const _exhaustiveCheck: never = shape
      return _exhaustiveCheck
  }
}
```

新增 `Triangle` 成员却不处理时，`shape` 在 `default` 分支被收窄为 `Triangle`，不能赋值给 `never`，从而产生编译错误。

## 特殊类型

### [重点] unknown 和 any 的区别

- `any` 放弃类型检查，可以对它做任何操作，也可以赋给任何类型。
- `unknown` 表示任何值，但更安全：对 `unknown` 做任何操作都是不合法的，必须先收窄或断言。
- 描述“能接受任意值、但函数体内不直接使用”的参数时用 `unknown`；返回不确定类型的值时也用 `unknown`。

```ts
function f1(a: any) {
  a.b() // OK
}

function f2(a: unknown) {
  a.b() // 报错：Object is of type 'unknown'
}

function safeParse(s: string): unknown {
  return JSON.parse(s)
}
```

### never 类型有什么用

- `never` 表示一个值不会再被观察到，例如总是抛异常或死循环的函数返回值。
- `never` 可以赋值给任何类型，但没有类型可以赋值给 `never`（除了 `never` 自身）。
- 常用于 `switch` 穷尽检查，确保所有联合成员都被处理。
- 条件类型中，过滤掉不匹配的成员时也常返回 `never`，联合类型中的 `never` 会被自动移除。

```ts
function fail(msg: string): never {
  throw new Error(msg)
}
```

### void 和 object 的区别

- `void` 表示函数没有返回值。
- `object` 表示任何非原始类型的值（不是 `string`、`number`、`bigint`、`boolean`、`symbol`、`null`、`undefined`）。
- `object` 不同于空对象类型 `{}`，也不同于全局类型 `Object`。在 TypeScript 中函数也被认为是 `object`。

## 工具类型

### [重点] 常用工具类型有哪些

| 工具类型 | 作用 |
| --- | --- |
| `Partial<T>` | 所有属性变为可选 |
| `Required<T>` | 所有属性变为必选 |
| `Readonly<T>` | 所有属性变为只读 |
| `Record<K, T>` | 构造 key 为 `K`、value 为 `T` 的对象类型 |
| `Pick<T, K>` | 从 `T` 中挑出属性 `K` |
| `Omit<T, K>` | 从 `T` 中排除属性 `K` |
| `Exclude<T, U>` | 从联合类型 `T` 中排除可赋给 `U` 的成员 |
| `Extract<T, U>` | 从联合类型 `T` 中提取可赋给 `U` 的成员 |
| `NonNullable<T>` | 排除 `null` 和 `undefined` |
| `Parameters<F>` | 取函数参数元组 |
| `ConstructorParameters<C>` | 取构造函数参数元组 |
| `ReturnType<F>` | 取函数返回值类型 |
| `InstanceType<C>` | 取构造函数实例类型 |

示例：

```ts
interface Todo {
  title: string
  description: string
  completed: boolean
}

type TodoPreview = Pick<Todo, 'title' | 'completed'>
type TodoWithoutDesc = Omit<Todo, 'description'>
type PartialTodo = Partial<Todo>
type TodoRecord = Record<'a' | 'b', Todo>

type T0 = Exclude<'a' | 'b' | 'c', 'a'> // 'b' | 'c'
type T1 = Extract<'a' | 'b' | 'c', 'a' | 'f'> // 'a'
type T2 = NonNullable<string | number | undefined> // string | number
type T3 = ReturnType<() => string> // string
type T4 = Parameters<(s: string) => void> // [s: string]
```

### 怎么实现 Partial 和 Pick

核心是映射类型加 `keyof`：

```ts
type MyPartial<T> = {
  [K in keyof T]?: T[K]
}

type MyPick<T, K extends keyof T> = {
  [P in K]: T[P]
}

type MyRecord<K extends keyof any, T> = {
  [P in K]: T
}
```

### 接口继承和交叉类型在冲突时有什么不同

继承时如果重写属性类型不兼容，会直接编译报错：

```ts
interface Colorful {
  color: string
}

interface ColorfulSub extends Colorful {
  color: number
}
// 报错：number 不能赋给 string
```

交叉类型不会报错，冲突属性的类型取交集，结果是 `never`：

```ts
interface Colorful {
  color: string
}

type ColorfulSub = Colorful & {
  color: number
}
// color 的类型是 never
```
