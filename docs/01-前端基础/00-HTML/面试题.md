# HTML 面试题

> 覆盖 HTML5、语义化、meta/SEO、Cookie 存储与浏览器渲染的常见问答，共 19 题。

## HTML5 与语义化

### [重点] HTML5 有哪些新特性移除了哪些元素

HTML5 现在已不是 SGML 的子集，主要增加了图像、位置、存储、多任务等能力。

新增能力：

- 绘画：`canvas`
- 媒介回放：`video`、`audio`
- 本地离线存储：`localStorage` 长期保存数据，浏览器关闭后不丢失；`sessionStorage` 的数据在浏览器关闭后自动删除
- 语义化更好的内容元素：`article`、`footer`、`header`、`nav`、`section`
- 表单控件：`calendar`、`date`、`time`、`email`、`url`、`search`
- 新技术：`Web Worker`、`WebSocket`、`Geolocation`

移除的元素：

- 纯表现元素：`basefont`、`big`、`center`、`font`、`s`、`strike`、`tt`、`u`
- 对可用性产生负面影响的元素：`frame`、`frameset`、`noframes`

兼容旧浏览器：

- IE8/IE7/IE6 可以通过 `document.createElement` 创建 HTML5 新标签，让这些浏览器识别新标签；识别后还需要补上标签的默认样式。
- 也可以直接使用成熟框架，例如 `html5shim`：

```html
<!--[if lt IE 9]>
  <script src="http://html5shim.googlecode.com/svn/trunk/html5.js"></script>
<![endif]-->
```

### [重点] 语义化的理解

- 简单来说：用正确的标签做正确的事情。
- 语义化让页面内容结构化，便于浏览器和搜索引擎解析。
- 在没有 CSS 的情况下也能以文档格式显示，并且容易阅读。
- 搜索引擎爬虫依赖标记确定上下文和关键词权重，利于 SEO。
- 让阅读源码的人更容易把网站分块，便于阅读、维护和理解。

### WEB 标准以及 W3C 标准是什么

标签闭合、标签小写、不乱嵌套、使用外链 CSS 和 JS、结构行为表现分离。

### 行内元素、块级元素、空（void）元素有哪些

行内元素不可以设置宽高，不独占一行；块级元素可以设置宽高，独占一行。

- 行内元素：`a`、`abbr`、`acronym`、`b`、`bdo`、`big`、`br`、`cite`、`code`、`dfn`、`em`、`i`、`img`、`input`、`kbd`、`label`、`q`、`samp`、`select`、`small`、`span`、`strong`、`sub`、`sup`、`textarea`、`tt`、`var`
- 块级元素：`address`、`caption`、`dd`、`div`、`dl`、`dt`、`fieldset`、`form`、`h1`–`h6`、`hr`、`legend`、`li`、`noframes`、`noscript`、`ol`、`ul`、`p`、`pre`、`table`、`tbody`、`td`、`tfoot`、`th`、`thead`、`tr`
- 空元素（常见）：`br`、`hr`、`img`、`input`、`link`、`meta`
- 空元素（少见）：`area`、`base`、`col`、`command`、`embed`、`keygen`、`param`、`source`、`track`、`wbr`

### XHTML 和 HTML 有什么区别

- 功能差别：XHTML 可兼容各大浏览器、手机以及 PDA，浏览器也能快速正确地编译网页。
- 书写习惯差别：XHTML 元素必须正确嵌套、闭合、区分大小写，文档必须拥有根元素。

### [重点] DOCTYPE 的作用与严格模式混杂模式如何区分

DOCTYPE 是 document type（文档类型）的缩写，位于文档最前面、标签之前，不是 HTML 标签。主要作用是告诉浏览器解析器使用哪种 HTML 规范或 XHTML 规范解析页面。

严格模式和混杂模式都是浏览器的呈现模式，使用哪种模式与网页中的 DTD（文件类型定义）有关，DTD 包含文档规则，例如 `loose.dtd`。

- 严格模式（标准模式）：浏览器按照 W3C 标准解析代码并呈现页面。
- 混杂模式（怪异模式 / 兼容模式）：浏览器按自己的方式解析，使用比较宽松的向后兼容方式显示页面。

### HTML5 为什么只需写 `<!DOCTYPE HTML>`

HTML5 不基于 SGML（标准通用标记语言），因此不需要引用 DTD（DTD 规定标记语言的规则，浏览器据此正确呈现内容），但仍需要 DOCTYPE 规范浏览器行为，让浏览器按应有的方式运行。

HTML 4.01 基于 SGML，所以需要引用 DTD，才能告知浏览器文档使用的文档类型。

## meta 与 SEO

### meta 标签的属性

- `name` 属性
  - `keywords`：关键字
  - `description`：描述
  - `viewport`：视口
  - `robots`：搜索引擎的索引方式
  - `renderer`：搜索引擎的渲染方式
  - `revisit-after`：搜索引擎的重访时间
- `http-equiv` 属性
  - `content-Type`：设定网页字符集
  - `X-UA-Compatible`：告知浏览器以何种方式渲染页面
  - `cache-control`：请求和响应的缓存机制
  - `expires`：网站过期时间
  - `refresh`：自动刷新并重新跳转到指定页面
  - `set-Cookie`：设置 Cookie

```html
<meta name="xxx" content="xxxx" />

<!-- 相当于设置 HTTP 响应头 -->
<meta http-equiv="参数" content="具体的描述" />
```

### [重点] 前端需要注意哪些 SEO

- 合理的 `title`、`description`、`keywords`：搜索对这三项的权重逐个减小。`title` 强调重点即可，重要关键词出现不要超过 2 次且要靠前，不同页面的 `title` 要不同；`description` 高度概括页面内容，长度合适，不过分堆砌关键词，不同页面要有所不同；`keywords` 列出重要关键词即可。
- 语义化的 HTML 代码，符合 W3C 规范：语义化代码让搜索引擎容易理解网页。
- 重要内容的 HTML 代码放在最前：搜索引擎从上到下抓取 HTML，有的搜索引擎对抓取长度有限制，要保证重要内容一定被抓取。
- 重要内容不要用 JS 输出：爬虫不会执行 JS 获取内容。
- 少用 `iframe`：搜索引擎不会抓取 `iframe` 中的内容。
- 非装饰性图片必须加 `alt`。
- 提高网站速度：网站速度是搜索引擎排序的重要指标。

## 存储与 Cookie

### [重点] cookies sessionStorage 和 localStorage 的区别

- `cookie` 是网站为了标示用户身份而存储在用户本地终端（Client Side）上的数据，通常经过加密。
- `cookie` 数据始终在同源的 HTTP 请求中携带（即使不需要），会在浏览器和服务器之间来回传递。
- `sessionStorage` 和 `localStorage` 不会自动把数据发给服务器，仅在本地保存。
- 存储大小：`cookie` 数据大小不能超过 4KB；`sessionStorage` 和 `localStorage` 虽然也有限制，但比 `cookie` 大得多，可以达到 5MB 或更大。
- 有效期：`localStorage` 存储持久数据，浏览器关闭后不丢失，除非主动删除；`sessionStorage` 数据在当前浏览器窗口关闭后自动删除；`cookie` 在设置的过期时间之前一直有效，即使窗口或浏览器关闭。

### 页面访问 Cookie 的限制条件

Cookie 指某些网站为了辨别用户身份、进行 session 跟踪而存储在用户本地终端上的数据。浏览以前访问过的网站时，网页中可能出现“你好 XXX”，这就是 Cookie 在起作用。

**1. 跨域问题**

Cookie 允许 Web 开发者保留用户的登录状态，但当站点有一个以上域名时就会出现问题。Cookie 规范规定一个 Cookie 只能用于一个域名，不能发给其他域名。因此在浏览器中为一个域名设置的 Cookie，对其他域名无效。

解决方式：

- 通过 Nginx 反向代理
- JSONP 方式请求

**2. 设置了 HttpOnly**

如果 Cookie 设置了 `HttpOnly` 属性，通过程序（JS 脚本、Applet 等）将无法读取 Cookie 信息，这样可以有效防止 XSS 攻击。

### Cookie 的作用与弊端

作用：

- 在客户端保存用户数据，起到简单的缓存和用户身份识别作用。
- 保存用户登录状态：登录成功后服务器生成特定 Cookie 返回客户端，客户端下次访问该域名下的任何页面都会携带该 Cookie，服务器检验后判断用户是否登录。
- 记录用户行为。

弊端：

- 增加流量消耗，每次请求都需要带上 Cookie。
- 存在安全隐患，Cookie 使用明文传输。Cookie 被拦截后，攻击者可以取得所有 session 信息。
- Cookie 有数量和长度限制。每个 domain 最多只能有 20 条 Cookie，每个 Cookie 长度不能超过 4KB，否则会被截掉。

### 介绍 Cookie 的属性

在 Chrome 控制台的 Application 选项卡中可以看到 Cookie 信息。一个域名下可能存在很多 Cookie 对象，但一个 Cookie 只能用于一个域名，不能发给其他域名。

![Chrome Application 面板中的 Cookie 信息](/assets/frontend/1397dcaf475a.png)

- `Name`：Cookie 名称。用 JavaScript 操作 Cookie 时注意对 Value 进行编码处理。
- `Value`：Cookie 的值。
- `Domain`：可以访问此 Cookie 的域名。二级域名能读取 `domain` 为顶级域名或自身的 Cookie，不能读取其他二级域名的 Cookie。要让 Cookie 在多个二级域名中共享，需要把 `domain` 设置为顶级域名；顶级域名只能获取 `domain` 为顶级域名的 Cookie。
- `Path`：可以访问此 Cookie 的页面路径。比如 `domain` 是 `abc.com`、`path` 是 `/test`，那么只有 `/test` 路径下的页面可以读取此 Cookie。
- `Expires`：Cookie 超时时间。设置后到达该时间 Cookie 失效；不设置时默认值是 Session，Cookie 会和 session 一起失效，浏览器关闭（整个浏览器，不是标签页）后失效。

```http
Set-Cookie: id=a3fWa; Expires=Wed, 21 Oct 2015 07:28:00 GMT;
```

会话性 Cookie 保存在客户端内存中，用户关闭浏览器时失效。有些浏览器提供会话恢复功能，这种情况下会话期 Cookie 也可能被保留。与会话性 Cookie 相对的是持久性 Cookie，保存在用户硬盘中，直至过期或被清除。注意设定的日期和时间只与客户端相关，与服务端无关。

- `Max-Age`：设置在 Cookie 失效之前需要经过的秒数。

```http
Set-Cookie: id=a3fWa; Max-Age=604800;
```

`Max-Age` 可以为正数、负数或 0：正数时浏览器会将其持久化，写入 Cookie 文件；负数表示会话性 Cookie；为 0 时立即删除 Cookie。如果 `Expires` 和 `Max-Age` 同时存在，`Max-Age` 优先级更高。

- `Size`：Cookie 大小。
- `HttpOnly`：为 `true` 时，只有 HTTP 请求头中会带有此 Cookie，不能通过 `document.cookie` 访问。
- `Secure`：设置是否只能通过 HTTPS 传递此 Cookie。使用 HTTPS 可以保护 Cookie 在浏览器和 Web 服务器之间传输时不被窃取和篡改。
- `SameSite`：控制跨站请求是否发送 Cookie，见下一题。

### [重点] SameSite 属性

Chrome 80 默认屏蔽第三方 Cookie，导致不少依赖跨站 Cookie 的应用出现问题，SameSite 也因此成为高频考点。

作用：让 Cookie 在跨站请求时不被发送，从而阻止跨站请求伪造攻击（CSRF）。

背景：HTTP/1.x 是无状态协议，同一个客户端连续两次发送请求，服务器识别不出这是同一个客户端。Cookie 不是为了解决通讯协议无状态的问题，而是为了解决客户端与服务端会话状态的问题，这个状态指后端服务的状态而非通讯协议的状态。

Cookie 的设置过程：

1. 客户端发送 HTTP 请求到服务器。
2. 服务器收到请求后，在响应头里添加 `Set-Cookie` 字段。
3. 浏览器收到响应后保存 Cookie。
4. 之后对该服务器的每一次请求，都通过 Cookie 字段把 Cookie 信息发送给服务器。

属性值：

- `Strict`：仅允许一方请求携带 Cookie，即只发送相同站点的 Cookie，当前网页 URL 与请求目标 URL 完全一致。
- `Lax`：允许部分第三方请求携带 Cookie。
- `None`：无论是否跨站都会发送 Cookie。

之前默认是 `None`，Chrome 80 后默认是 `Lax`。

跨域和跨站不同：

- 同站（same-site）/ 跨站（cross-site）与第一方（first-party）/ 第三方（third-party）等价。
- 同源策略（SOP）中的同源（same-origin）/ 跨域（cross-origin）是另一个概念。
- 同源要求协议、主机名、端口一致。例如 `https://www.taobao.com/pages/...` 的协议是 `https`、主机名是 `www.taobao.com`、端口是 `443`。
- Cookie 的同站判断更宽松：只要两个 URL 的 eTLD+1 相同即可，不考虑协议和端口。eTLD 是有效顶级域名，注册于 Mozilla 维护的公共后缀列表（PSL），如 `.com`、`.co.uk`、`.github.io`；eTLD+1 是有效顶级域名加二级域名，如 `taobao.com`。
- 举例：`www.taobao.com` 和 `www.baidu.com` 是跨站；`www.a.taobao.com` 和 `www.b.taobao.com` 是同站；`a.github.io` 和 `b.github.io` 是跨站。

从 `None` 改成 `Lax` 后，Post 表单、iframe、AJAX、Image 这四种情况从以前的跨站会发送三方 Cookie，变成不发送：

![SameSite 改为 Lax 后各场景 Cookie 发送情况](/assets/frontend/28e1bb722479.png)

- Post 表单：CSRF 常举的例子。
- iframe：嵌入的 Web 应用有很多是跨站的，都会受影响。
- AJAX：可能影响部分前端取值行为和结果。
- Image：图片一般放 CDN，大部分情况不需要 Cookie，影响有限；但如果引用需要鉴权的图片，可能受影响。

Script 方式也不会发送 Cookie，像淘宝的大部分 JSONP 请求，涉及跨站时也可能受影响。

如果不处理，常见问题包括：天猫和飞猪页面请求淘宝域名接口获取登录信息时 Cookie 丢失，用户无法登录；淘宝部分页面内嵌支付宝确认付款页面、天猫内嵌淘宝登录页面时，付款和登录失败；阿里妈妈在今日头条、网易、微博等站点投放的 iframe 广告无法准确推荐；埋点系统把用户 id 放在 Cookie 中上报时受影响；防恶意请求系统弹出验证码并通过 Cookie 记录验证状态时，会一直弹验证码；天猫商家后台跨域请求因没有 Cookie 拿不到数据。

解决方案是把 `SameSite` 设置为 `None`。

## 浏览器与渲染

### 从浏览器地址栏输入 URL 到显示页面的步骤

**简略回答**

- 浏览器根据请求的 URL 交给 DNS 域名解析，找到真实 IP，向服务器发起请求。
- 服务器交给后台处理完成后返回数据，浏览器接收文件（HTML、JS、CSS、图像等）。
- 浏览器对加载到的资源（HTML、JS、CSS 等）进行语法解析，建立相应的内部数据结构（如 HTML 的 DOM）。
- 载入解析到的资源文件，渲染页面，完成。

**详细回答**

1. 从浏览器接收 URL 到开启网络请求线程（可以展开浏览器的机制以及进程与线程之间的关系）。
2. 开启网络线程到发出一个完整的 HTTP 请求（涉及 DNS 查询、TCP/IP 请求、五层因特网协议栈等）。
3. 从服务器接收到请求到对应后台接收到请求（可能涉及负载均衡、安全拦截以及后台内部处理）。
4. 后台和前台的 HTTP 交互（包括 HTTP 头部、响应码、报文结构、Cookie 等，可以提静态资源的 Cookie 优化，以及编码解码，如 gzip 压缩）。
5. 单独拎出来的缓存问题（HTTP 缓存、`ETag`、`Cache-Control` 等）。
6. 浏览器接收到 HTTP 数据包后的解析流程（解析 HTML、词法分析生成 DOM 树，解析 CSS 生成 CSS 规则树，合并成 Render 树，然后 layout、painting 渲染、复合图层合成、GPU 绘制、外链资源处理、`loaded` 和 `DOMContentLoaded` 等）。
7. CSS 的可视化格式模型（元素的渲染规则，如包含块、控制框、BFC、IFC 等概念）。
8. JS 引擎解析过程（解释阶段、预处理阶段、执行阶段生成执行上下文、VO、作用域链、回收机制等）。
9. 其他（可以拓展跨域、Web 安全、Hybrid 模式等）。

### 对浏览器内核的理解

浏览器内核主要分成两部分：渲染引擎（layout engineer 或 Rendering Engine）和 JS 引擎。

- 渲染引擎：负责取得网页内容（HTML、XML、图像等）、整理信息（例如加入 CSS 等），计算网页显示方式，然后输出到显示器或打印机。不同内核对于网页语法的解释不同，渲染效果也不同。浏览器、电子邮件客户端以及其他需要编辑、显示网络内容的应用程序都需要内核。
- JS 引擎：解析和执行 JavaScript，实现网页动态效果。
- 最开始渲染引擎和 JS 引擎没有区分得很明确，后来 JS 引擎越来越独立，内核就倾向于只指渲染引擎。

### [重点] iframe 有哪些缺点

- `iframe` 会阻塞主页面的 `onload` 事件。
- 搜索引擎的检索程序无法解读这种页面，不利于 SEO。
- `iframe` 和主页面共享连接池，而浏览器对相同域的连接有限制，所以会影响页面的并行加载。

使用 `iframe` 之前需要考虑这两个缺点。如果必须使用，最好通过 JavaScript 动态给 `iframe` 添加 `src` 属性值，这样可以绕开以上两个问题。

### 网页验证码是干嘛的，解决什么安全问题

- 区分用户是计算机还是人的公共全自动程序，可以防止恶意破解密码、刷票、论坛灌水。
- 有效防止黑客对某一个特定注册用户用特定程序暴力破解方式进行不断的登录尝试。

## 性能优化

### 如何进行网站性能优化

- 内容方面
  - 减少 HTTP 请求：合并文件、CSS 精灵、inline Image。
  - 减少 DNS 查询：DNS 缓存、将资源分布到恰当数量的主机名。
  - 减少 DOM 元素数量。
- Cookie 方面
  - 减小 Cookie 大小。
- 服务器方面
  - 使用 CDN。
  - 配置 `ETag`。
  - 对组件使用 Gzip 压缩。
- 图片方面
  - 优化图片：根据实际颜色需要选择色深、压缩。
  - 优化 CSS 精灵。
  - 不要在 HTML 中拉伸图片。
- CSS 方面
  - 将样式表放到页面顶部。
  - 不使用 CSS 表达式。
  - 使用 `<link>`，不使用 `@import`。
- JS 方面
  - 将脚本放到页面底部。
  - 将 JavaScript 和 CSS 从外部引入。
  - 压缩 JavaScript 和 CSS。
  - 删除不需要的脚本。
  - 减少 DOM 访问。
