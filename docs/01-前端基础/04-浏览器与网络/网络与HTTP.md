# 网络与 HTTP

> 按 HTTP、浏览器缓存、跨域、TCP/OSI 和浏览器渲染整理网络高频知识，题目索引见[面试题](./面试题.md)。

## HTTP

### [重点] 常用状态码

- `200`：请求成功
- `301`：永久重定向
- `302`：临时重定向
- `304`：自从上次请求后，请求的网页未修改，服务器返回响应但不返回内容（从缓存中读取）
- `400`：服务器不理解请求的语法
- `403`：Forbidden，服务器理解客户端的请求，但拒绝执行
- `404`：请求的资源（网页等）不存在
- `413`：请求体过大，超出服务器的处理能力上限
- `414`：请求 URL 太长，服务器无法处理
- `500`：内部服务器错误
- `502`：Bad Gateway，作为网关或代理的服务器执行请求时，从远程服务器收到了无效响应

### HTTP 报文的组成部分

- 请求报文：请求行、请求头、空行、请求体
  - 请求行：HTTP 方法、页面地址、HTTP 协议及版本
  - 请求头：key-value 值，告诉服务端需要的内容
  - 空行：告知服务端下面是请求体
  - 请求体：数据部分
- 响应报文：状态行、响应头、空行、响应体

### HTTPS 的加密方式

HTTPS 通过 TLS 对数据加密，同时使用对称加密（AES）和非对称加密（RSA）。

### [重点] HTTP2 和 HTTP1 的区别

- HTTP/1 同时只能请求 6 个连接；HTTP/2 实现了多路复用，可以复用一个 TCP 连接。
- HTTP/1 通过文本方式传输数据，HTTP/2 通过二进制传输。
- HTTP/2 对 header 进行了压缩。
- HTTP/2 可以由服务端 push 推送。

### HTTPS 和 HTTP 的区别

- 安全方面：HTTP 使用无状态、明文传输；HTTPS 实际上是 HTTP + SSL 协议组成的加密传输协议。
- 响应速度：理论上 HTTP 更快，只需要三次握手；HTTPS 在三次握手之外还需要一次 SSL 握手。
- 端口：HTTP 默认 80 端口，HTTPS 默认 443 端口。
- 资源消耗：HTTPS 构建在 SSL 之上，会消耗更多服务端资源。
- 展示方面：HTTPS 会在浏览器地址栏显示一个绿色的锁。

## 浏览器缓存

### 浏览器缓存的意义

- 避免冗余的数据传输，节省流量。
- 加快用户访问速度。
- 减小服务器压力。

### 缓存策略

第一次请求数据时，浏览器没有对应的缓存数据，需要请求服务器；服务器返回数据后，浏览器会把请求数据缓存。

当浏览器有缓存数据后，可以根据是否向服务器发送请求，把缓存分为协商缓存与强缓存。

### 强缓存

命中缓存后，不会向服务器发送请求，直接从本地获取。返回状态码为 `200 (from disk cache)` 或 `200 (from memory cache)`。

### 协商缓存

缓存过期后，浏览器向服务器发送请求，协商对比服务端和本地的资源，验证本地资源是否失效。若服务器资源与本地资源相同，则命中缓存，返回 304；否则直接请求服务器资源。

协商缓存的响应结果不仅验证资源有效性，还会更新浏览器缓存。

`Age: 0` 表示命中了代理服务器的缓存，`age` 值为 0 表示代理服务器刚刚刷新了一次缓存。

### 强缓存与协商缓存的关系

相同点：命中缓存资源后都从本地读取资源。

不同点：

- 强缓存生效时，不需要再向服务端发起请求。
- 协商缓存不管是否使用缓存，都必须向服务器发送一个请求来协商。

### 优先级

两类缓存规则同时存在时，`强缓存 > 协商缓存`。

执行强缓存规则时，如果缓存生效，直接使用缓存，不再执行协商缓存规则；如果强缓存规则不生效，则进行协商缓存判断。

### 缓存流程总结

1. 浏览器第一次请求数据时，缓存中没有对应数据，请求服务器；服务器返回数据后，浏览器把数据缓存。
2. 浏览器再次访问同一 URL，会根据请求资源是否过期向服务器发送不同请求，分为强缓存和协商缓存。
3. 若资源未过期（`Expires` 和 `Cache-Control`），命中强缓存，不向服务器发送请求，直接从缓存读取。
4. 若资源显示过期（`If-Modified-Since` / `Last-Modified` 和 `If-None-Match` / `ETag`），则向服务器发送请求，协商对比服务器资源，验证是否失效。若相同，命中协商缓存，返回 304；否则直接请求服务器。

### 清除浏览器缓存

在 meta 标签中令 `cache-control` 为 `no-cache`，或 `expires` 为 `0`：

```html
<meta http-equiv="Cache-Control" content="no-cache, must-revalidate" />
<meta http-equiv="expires" content="0" />
```

### 哪些内容不能被浏览器缓存

1. HTTP 头中 `cache-control` 为 `no-cache` 或 `max-age: 0`。
2. 需要根据 Cookie 和输入内容生成的动态请求。
3. 经过 HTTPS 加密的请求。
4. POST 请求不可以被缓存。
5. HTTP 响应头中不含 `Last-Modified` / `ETag`，也不包含 `Cache-Control` / `Expires` 的请求无法被缓存。

## 跨域与前后端通信

### 前后端的通信方式

- Ajax：同源下的通信。
- WebSocket：不受同源策略限制。
- CORS：支持跨域通信，也支持同源通信。

### [重点] 跨域的解决方案

协议、域名、端口任一不同即为跨域。

1. JSONP 跨域
2. `location.hash` 跨域
3. `postMessage` 跨域
4. WebSocket 跨域
5. CORS 跨域（后台设置响应头）
6. 反向代理（Vue 项目中经常用到）
7. Nginx 代理

## TCP/UDP 与 OSI

### [重点] TCP 的三次握手和四次挥手

**三次握手**

1. 客户端向服务端发送 SYN 请求包，询问服务端能不能收到请求。
2. 服务端接收后向客户端发送 ACK 确认包，告诉客户端能收到。
3. 客户端向服务端发送 ACK 确认包，告诉服务端我也能收到；然后客户端进入准备状态，服务器接收后也进入准备状态。

**四次挥手**

1. 客户端向服务端发送 FIN 请求包，告诉服务端要断开连接。
2. 服务端收到后发送 ACK 确认包，告诉客户端收到了断开请求。
3. 服务端有未传完的数据会继续传完，然后向客户端发送 FIN 请求包，告诉客户端可以断开连接了。
4. 客户端收到后向服务端发送 ACK 确认包，然后客户端断开连接，服务端收到后也断开连接。

### UDP 和 TCP

与 TCP 相比，UDP 更轻便，不需要经历建立连接和断开连接的阶段，适合直播等场景。

### [重点] OSI 七层模型

ISO 为了使网络应用更普及，推出了 OSI 参考模型。

**（1）应用层**

OSI 参考模型中最靠近用户的一层，为用户提供应用接口和直接可用的网络服务。常见协议有 HTTP、HTTPS、FTP、POP3、SMTP 等。

- HTTP（Hyper Text Transfer Protocol，超文本传输协议）或 HTTPS：后端设计数据接口时常用。
- FTP（File Transfer Protocol，文件传输协议）：资源网站、网盘等可能基于此协议。
- SMTP（Simple Mail Transfer Protocol，简单邮件传输协议）：邮箱验证码登录等场景会用到。

**（2）表示层**

提供各种用于应用层数据的编码和转换功能，确保一个系统的应用层发送的数据能被另一个系统的应用层识别。必要时提供标准表示形式，把计算机内部的多种数据格式转换成通信中采用的标准表示形式。数据压缩和加密也属于表示层能力。

例如，为了方便数据传输，可以使用 base64 对数据编解码；按功能划分，base64 工作在表示层。

**（3）会话层**

负责建立、管理和终止表示层实体之间的通信会话。通信由不同设备中的应用程序之间的服务请求和响应组成。

**（4）传输层**

建立主机端到端的连接，为上层协议提供端到端的可靠、透明数据传输服务，包括差错控制和流量控制。该层向高层屏蔽下层数据通信细节，使高层用户看到的是两个传输实体之间一条主机到主机、可由用户控制和设定的可靠数据通路。TCP、UDP 就在这一层。端口号就是这里的“端”。

**（5）网络层**

通过 IP 寻址建立两个节点之间的连接，为源端传输层送来的分组选择合适的路由和交换节点，正确无误地按照地址传送给目的端的传输层，也就是通常说的 IP 层。IP 协议是 Internet 的基础。可以这样理解：网络层规定数据包的传输路线，传输层规定数据包的传输方式。

**（6）数据链路层**

将比特组合成字节，再将字节组合成帧，使用链路层地址（以太网使用 MAC 地址）访问介质，并进行差错检测。网络层规划数据包的传输路线，数据链路层就是传输路线本身，同时还增加了差错控制功能。

**（7）物理层**

最终信号的传输通过物理层实现，通过物理介质传输比特流，规定电平、速度和电缆针脚。常用设备有集线器、中继器、调制解调器、网线、双绞线、同轴电缆等。

**对等通信**

为了使数据分组从源传送到目的地，源端 OSI 模型的每一层都必须与目的端的对等层进行通信，这种通信方式称为对等层通信。每一层通信过程中使用本层自己的协议。

### HTTPS 的加密在 OSI 的哪一层

HTTPS 的加密在 OSI 七层模型中的表示层。

## 浏览器渲染

### [重点] 在浏览器中输入网址到页面展示会经历什么

1. 浏览器输入 URL。
2. 查找缓存：浏览器先查看浏览器缓存、系统缓存、路由缓存中是否有该地址页面，有则显示，没有则进行下一步。
3. DNS 域名解析：浏览器向 DNS 服务器发送请求，解析 URL 域名对应的 IP 地址（DNS 服务器基于 UDP，因此会用到 UDP 协议）。
4. 建立 TCP 连接：解析出 IP 地址后，根据 IP 地址和默认端口与服务器建立 TCP 连接。
5. 发起 HTTP 请求：浏览器发起读取文件的 HTTP 请求，该请求作为 TCP 三次握手的第三次数据发送给服务器。
6. 服务器响应并返回结果：服务器对浏览器请求做出响应，并把对应的 HTML 文件发送给浏览器。
7. 关闭 TCP 连接：通过四次挥手释放 TCP 连接。
8. 浏览器渲染：客户端解析 HTML 内容并渲染。
   1. 构建 DOM 树：词法分析后解析成 DOM 树，由 DOM 元素及属性节点组成，树的根是 `document` 对象。
   2. 构建 CSS 规则树：生成 CSS Rule Tree。
   3. 构建 Render 树：浏览器把 DOM 和 CSSOM 结合，构建渲染树。
   4. 布局（Layout）：计算每个节点在屏幕中的位置。
   5. GPU 绘制（Painting）：遍历 Render 树，使用 UI 后端层绘制每个节点。

### 浏览器的重绘与重排回流

- 重排/回流（Reflow）：当 DOM 变化影响元素的几何信息，浏览器需要重新计算元素的几何属性，把元素安放在界面中的正确位置。表现为重新生成布局、重新排列元素。
- 重绘（Repaint）：元素外观发生改变，但没有改变布局，重新把元素外观绘制出来的过程。表现为某些元素的外观被改变。

### 如何触发重排和重绘

重排的触发条件：

- 增加、删除、修改、移动 DOM
- 修改 CSS 样式
- 改变浏览器窗口大小
- 页面滚动
- 修改网页默认字体
- 获取一些 style 信息时，如 `offsetWidth`、`offsetHeight`

重绘的触发条件：

- DOM 改动
- CSS 某些样式改动，比如颜色

### 如何避免重排重绘

- 集中改变样式，不要一条一条地修改 DOM 样式。
- 不要把 DOM 节点的属性值放在循环里当成循环变量。
- 动画元素使用定位，修改它们的 CSS 时不会重排。
- 不使用 table 布局。
- 尽量只修改定位元素，例如 `position: absolute` 或 `fixed` 元素，对其他元素影响不大。
- 动画开启 GPU 加速，使用 3D 变化，例如 `translateZ(0)`。
