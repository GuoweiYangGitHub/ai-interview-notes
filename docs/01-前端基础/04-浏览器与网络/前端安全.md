# 前端安全

> 常见攻击方式、SQL 注入的成因与防护、前后端加密方案和基础运维安全。

## 常见攻击方式

- XSS 攻击
- CSRF 攻击
- SQL 注入

## SQL 注入

### 前端怎么防止 SQL 注入

防止 SQL 注入唯一可靠的方式是验证输入和参数化查询。

开发者必须检查所有用户输入，而不是仅检查网页表单中的输入（比如登录表单）。必须移除潜在的恶意代码因素，比如单引号。线上环境屏蔽数据库错误也是好主意，因为结合数据库错误，SQL 注入攻击将获得更多数据库相关信息。

### SQL 注入的危害

- 可以添加、编辑、删除数据库中的数据。
- 可以拿到其他用户的凭证，伪装成这些用户。
- 甚至可以拿到数据库管理员权限，窃取数据。
- 影响应用的可用性。
- 可以以 SQL 注入作为初始手段，攻击防火墙背后的内网。

### SQL 注入攻击的过程及原因

为了发起 SQL 注入攻击，攻击者首先需要在网站或应用程序中找到易受攻击的用户输入。这些输入被有漏洞的网站或应用程序直接用于 SQL 查询语句。攻击者可以创建这些输入内容，这些内容往往被称为恶意载体，是攻击过程中的关键部分。随后攻击者把内容发送出去，恶意的 SQL 语句便会在数据库中执行。

- 攻击者可利用 SQL 注入从数据库中得到其他用户的凭证，之后伪装成这些用户，其中甚至可能包括拥有所有数据库权限的管理员。
- SQL 可用于从数据库中选择并输出数据，注入漏洞允许攻击者访问数据库服务中的所有数据。
- SQL 可用于修改或添加数据。例如在金融产品中，攻击者能利用注入修改余额、取消交易记录或给自己的账户转账。
- SQL 可用于删除记录甚至删除数据表。即使管理员做了备份，数据恢复之前被删除的数据仍会影响应用可用性，而且备份很可能没有覆盖最近的数据。
- 在某些数据库服务中，可通过数据库服务访问操作系统。这种设计可能是有意或无意造成的。此时攻击者会把 SQL 注入作为初始手段，进而攻击防火墙背后的内网。

### 预防 SQL 注入

- 培养并保持安全意识。
- 不要信任任何用户输入。
- 使用白名单而不是黑名单：不要基于黑名单过滤输入，聪明的攻击者总能找到绕过方法；应尽可能只使用严格的白名单，对用户输入进行验证和过滤。
- 采用最新的技术。
- 采用经过验证的机制。
- 周期性扫描：SQL 注入漏洞可能由开发者引入，也可能由外部库、模块或软件引入。应使用网站漏洞扫描器（例如 Acunetix）周期性扫描网站；如果使用 Jenkins，可以安装 Acunetix 插件，在每次构建时自动扫描。

## 页面加密

### 常见的加密方法

- AES / DES 加密：对称加密。
- Base64 编码：不是加密，可逆，不能用于保密。
- MD5：哈希算法。
- SHA-512：哈希算法，不可逆。
- RSA 加密：非对称加密，运行速度比 AES 慢。

### AES 对称加密的特点

优点：算法公开、计算量小、加密速度快、加密效率高。

缺点：

- 交易双方使用同样的钥匙，安全性得不到保证。
- 密钥管理困难，使用成本较高。

### 前后端交互如何保证数据的安全性

用 AES（对称加密）和 RSA（非对称加密）配合使用：

1. 客户端启动，发送请求到服务端。服务端用 RSA 算法生成公钥（public1）和私钥（prikey1），把公钥返回给客户端。
2. 客户端拿到公钥（public1）后，自己在前端生成公钥（public2）和私钥（prikey2），并用 public1 加密 public2，传输给服务端。
3. 服务端接收后用私钥（prikey1）解密，拿到客户端的公钥（public2）。
4. 服务端生成一个 AES 的 16 位 key，并使用公钥（public2）加密后传输给客户端。
5. 客户端获取到 key 后，通过私钥（prikey2）解密，拿到 AES 加密的 key。
6. 客户端用该 key 进行数据传输，整个流程结束。

### 前端秘钥怎么存储

秘钥存储在后端，通过 AES + RSA 配合把秘钥拿到。

### 添加加密后接口访问速度的变化

没有影响。

## 服务器与运维安全

### 黑客上传文件到服务器后如何入侵系统

暂且认为一个服务器就是一个 IP（服务器和 IP 在本质上仍有很大区别）。黑客拿到一个 IP 后，总体上会分三个步骤慢慢渗透：

1. C 段渗透：C 段就是和服务器同一网段的一台主机。C 段渗透是通过同一网段的主机，对目标 IP 进行 ARP 等手段的渗透。
2. 社会工程学：通俗讲就是欺骗，例如通过网站钓鱼等方式让用户自己把重要信息泄露出去。
3. 服务渗透：服务器上会开启很多服务，比如 MySQL、FTP、RDP、Web 等。黑客可以通过这些服务用特殊手段渗透服务器。Web 端又可以通过 SQL 注入、上传漏洞、XSS、包含漏洞、代码执行、逻辑漏洞等渗透服务器。

### Linux 修改文件读取权限

`chmod -R 777` 的三个 7 分别表示：

- 第一个 7：文件所有者访问权限。
- 第二个 7：群组访问权限。
- 第三个 7：其他人访问权限。

`r`（read）、`w`（write）、`x`（execute）分别对应读、写、执行，权限值为 4、2、1。

### 怎么让自己的网站不被爬虫爬

- 限制 `User-Agent` 字段：`User-Agent` 能识别用户使用的操作系统、版本、CPU、浏览器等信息。如果请求来自非浏览器，就能识别为爬虫并阻止抓取。
- 限制 IP：恶意爬虫的请求频率往往比正常流量高，找出这些 IP 并限制访问，可以有效降低恶意爬虫造成的危害。
- 添加验证码：在登录页等页面添加验证码，识别正常流量和恶意爬虫。不过如今爬虫技术已经能解决验证码问题，例如二值化、中值滤波去噪等。
- 限制 Cookie：根据业务需求限制 Cookie，要求用户登录后才能使用某些功能或权限，并针对同一账号的访问速度进行限制。
- 使用爬虫管理产品：可以使用防火墙产品防范爬虫，比如阿里云、腾讯云。
